## 2. Engine / Vio 永久定位

Continuity Engine 是持续存在的数字主体本身，是 Subject Authority 和 SubjectState 唯一权威；它不是 Vio Backend、Vio Plugin、Vio Agent、聊天机器人、Prompt Manager、Workflow Engine、普通 Assistant 或普通 Agent Framework。

Vio 是主体可使用的第一个 World Adapter / Reality Layer。两边仓库、进程、数据库、数据根目录、测试和生命周期彼此独立，只通过冻结的版本化契约协作：

```text
用户
  ↓
Vio 前端
  ↓
Vio 平台后端 / 第一 World Adapter
  ↕  冻结的版本化契约
Continuity Engine / Subject Authority
```

`Vio unavailable` 只能表示主体失去一条现实路径，不能推导为 `Subject unavailable`。P00 是接口冻结、运行断开和独立升级的起点；历史本地连接能力继续保留，但 Engine 的施工、测试和存在均不得依赖 Vio 进程存活。P22 才是第一正式 World Adapter 的生产重连阶段。

## 6. 永久权威与恢复边界

- SubjectState 是当前主体状态的唯一权威；Event 是历史事实权威；Timeline 只能是 Event Store 的可查询投影。
- Observation、模型文本、CapabilityResult、ToolResult 和平台投影都不能直接成为 StateMutation。
- 所有长期状态变化只能经合法 Action Gate 与 `Event / StateMutation → Evolution → SubjectState`。
- P01 只服务测试、实验和 Research Sandbox 的 Snapshot/Rollback。
- P17 可以复用 P01 的恢复设计与验证方式，但不能把 P01 当作正式主体恢复能力。P17 阶段本身的直接依赖只有 P16 `ACCEPTED`。
- P20/P21 承担正式 Subject、Owner Domain 和生产恢复，但不是 P17 阶段的前置依赖。P17 可以建设并验收 Execution Engine、World/Capability Layer、Reality Boundary、幂等、补偿、未知结果处理和能力门禁。
- 依赖正式 Subject、Owner Domain 或生产恢复的高风险现实能力，在 P20/P21 验收前必须保持 `RECOVERABILITY_NOT_READY / NOT_READY / Disabled` 或正式 Feature Gate 关闭状态。这是能力开放门，不是 P17 的反向阶段依赖，也不授权提前施工 P20/P21。
- 禁止用 Git reset、测试快照或删除数据目录改写正式主体历史。

## 7. 唯一现实行动链与 Reality Boundary

```text
Subject
→ Thought
→ Desire
→ Will
→ Decision
→ Structured Action
→ Capability Resolution
→ Permission / Resource / Recoverability Check
→ Reality Boundary
→ World Adapter
→ Reality Effect
```

Reality Boundary 只判断已经形成的行动能否影响现实并控制现实副作用。它不得限制、修改或审查 Thought、Emotion、Desire、Will、Personality、Relationship、Self-Narrative 或主体内部心理冲突。
