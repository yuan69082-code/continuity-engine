## R05：拒绝决定与分配共用事务内身份门

根因：`ResourceManager.request_resources` 的 request_id / 已分配 session 快速检查在仓储事务外。`save_allocation` 已在持有 `_RESOURCE_WRITE_LOCK` 时检查稳定身份，但 `save_decision` 只检查随机生成的 decision_id。两个请求均通过服务检查后，拒绝分支可以追加重复决定，也可以在原批准结果之后追加同一 request_id 的拒绝决定。

唯一运行代码改动位于 [json_resource_repository.py](../../src/continuity_engine/storage/json_resource_repository.py)：抽出既有身份检查，由 `save_allocation` 与 `save_decision` 在同一个已有写锁内、读取当前文档之后、写入之前调用。request_id 在全部已有决定中唯一；已分配 session 在 usage_records 中检查。后来的重复或冲突均明确 `ResourceValidationError`。没有第二账本，没有删除历史，没有更换身份，没有服务入口无锁补丁。既有状态 revision、usage_id、decision_id 和分配一致性检查保留。

新增正式并发回归让两个独立 Repository/Manager 同时到达 policy，证明二者均已越过服务入口检查，然后固定首个合法结果。覆盖拒绝/拒绝、批准/拒绝、拒绝/批准、批准/批准，以及不同 request_id 对同一已分配 session 的拒绝。每项同时断言后续异常类型、首结果字节完全不变、决定/usage 数量、实际扣费；合法原分配可重启结算为 8 tokens。正常拒绝、用新身份再次拒绝、用新身份获得分配与结算保留。

责任边界仍是现有本机线程共享仓储事务，不扩展为跨进程或分布式存储保证。
