## R1 当前表达授权与事实恢复分开

根因：原 `decide()`/`verify(current=True)` 只核验 Context 来源和保存的 ActionDecision，旧 expression.emit 回执被间接当作仍可输出正文的许可。

修复位于 `expression_policy_service.py`、内部 `domain/expression.py` 和 `continuity_interaction_service.py`：首次呈现、Port 返回后和当前消费都通过原 `ActionService.assess_local_action`，使用实际 expression.emit CapabilityBinding 的类型、permission、cost、正确 subject/environment/target 及 `core.clock()`。沿用当前 ResourceLimits、confirmation、Recoverability 和 Reality Boundary 接口，检查过程只读，不预占、不扣费、不调用 execute 或生成新 ActionSession。

确认接口复用 InternalActionRequest 的**只读身份视图**：绑定原 operation、request、Thinking、Action、Context 和表达 capability，具有稳定 key；只传给既有确认/边界 Port，不注册至 capability ledger、不投递、不创建第二账本。它不是新的 Thinking/Action 意图授权来源；真实许可与确认仍由原 Port 决定。P13 TEST Fixture 明确为这一精确视图提供一次确认，后续清除 key 或撤回确认不会被同 Fixture 的重放补回。宿主未提供该确认时失败关闭，不能凭旧成功回执补签。

已形成的 SILENCE 和 PLATFORM_DENIED 均无正文、无 Presentation 调用，不要求新增 expression.emit 执行；它们仍重验原绑定与来源，不伪造成授权输出。

新增 `ExpressionAccessError` 区分当前不可消费和记录损坏。submit/query 对当前拒绝不返回原正文；`expression_outcome` 先核验原 Action/Evolution/完成事实，再返回 `CURRENTLY_UNAVAILABLE`、空 artifact 和必要事实 identity/revision/update ID。UNKNOWN/冲突回执仍失败关闭，不能被此状态隐藏。原事实完成恢复沿用既有 journal，不重复副作用、计费或 revision。

## R2 仅使用获准 Context 的样式依据

根因：表达服务重新加载完整 SubjectState 并读取偏好，绕过 Router 未纳入或 exact-reference 已拒绝的材料。

修复只在 `ExpressionPolicyService`：使用已组装 snapshot 中的 `CONFIRMED_STATE` / `engine.subject-state` 精确片段，不再直接读取完整 SubjectState 作为样式输入。identity 提供 concise/emphasis；relationship 提供 formal；emotion_state 通过已有 `EmotionState.effective_at` 在原可信 Perception 时间计算同一确定性投影。未获准片段不能借 `context.effective_emotion` 旁路使用。

片段不存在时采用不依赖它的默认：无 identity 则不压缩/不强调；无 relationship 则 plain；无 emotion 则不以情绪强调。被选中来源在调用期间失效则拒绝完成。重复或含缺失/矛盾标记的样式依据失败关闭。来源重验继续使用原 `core.current()` 的 ACL、版本、hash 与 Composer resolver，没有新检索路径。

`state_hash` 现在绑定实际获准样式片段的 reference/fragment/version/hash 集合；字段为内部 P13 类型，不是完整 SubjectState 的可见摘要。reason_codes 区分各类片段 USED / ABSENT，不再笼统声称所有偏好均获准。Trace 不记录偏好正文、表达正文、秘密或隐藏推理。原事实、态度、Memory、SubjectState、关系及 EvolutionProposal 不因呈现而改写。

初版 P13 未验收产物的旧整体 state_hash 与新投影语义不同；不迁移/改写原 journal。原记录可按原绑定核验事实，但当前消费须符合修复后规则，不能自动升级旧未获准样式。P00—P12 真正旧格式、Feature Gate 关闭等兼容由原测试保留。
