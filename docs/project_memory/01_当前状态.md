## 阶段完成度

本档案使用以下口径：

- **已完成：** 当前代码中存在完整的 v0.1 核心实现与对应测试。
- **部分完成：** 内部结构或适配接口已经存在，但统一入口、持久化或真实集成仍不完整。
- **未实现/未来规划：** 只有边界设计或计划，没有真实外部能力。

按实际施工顺序归一化后，当前状态为：

1. SubjectState 最小持久化：**已完成**。
2. Event 与 Evolution：**已完成核心模块**。
3. Memory 管理层：**部分完成**；检索请求、相关性判断和影响记录接口已完成，外部长期记忆库未实现。
4. Awakening System：**部分完成**；周期、会话和单次唤醒流程已完成，后台定时器与统一资源入口未实现。
5. Thinking Engine：**部分完成**；直接接收 PerceptionResult，ThinkSession、Provider 和预算接口已完成，真实模型未接入。
6. Perception Engine：**已完成 v0.1 确定性感知层**。
7. Action Engine：**已完成决策规划层**；真实执行属于未来独立阶段，ActionSession 持久化尚未完成。
8. Permission Continuity Layer：**已完成内部权限连续状态层**；真实平台权限未接入。
9. Personality Evolution & Self Learning：**部分完成**；受控学习框架已完成，自动行为分析和模型学习未实现。
10. Token & Resource Management：**部分完成**；资源状态、管理器和检查入口已完成，但尚未强制所有路径使用统一资源入口。
11. API / MCP / Skill Adapter：**部分完成**；进程内 API 和适配器设计已完成，真实 MCP 与平台 Skill 未实现。
12. Frontend Integration：**部分完成**；最小本地前端可运行，不是生产前端。

原规划在 Action 之后重新使用了“第五、六、七阶段”编号。档案统一采用上述施工序号，并在路线图保留原编号映射。阶段曾完成验收不等于所有最终外部能力均已实现。

## 当前运行状态

### 验证结果

- 在项目根目录设置 `PYTHONPATH=src` 后执行 `python -m unittest discover -s tests -q`：87 项测试通过。
- CLI 入口已建立：`continuity-engine`。
- 本地前端入口已建立：`continuity-frontend` 或 `python -m continuity_engine.frontend`。
- 本地前端首次启动需要显式初始化：`python -m continuity_engine.frontend --initialize`。
- 默认本地地址：`http://127.0.0.1:8765`。
- Node.js 语法检查曾用于前端 JavaScript；当前环境可用 Node v22.23.1。

### 数据状态

- 默认本地运行数据位于 `.continuity-data/`。
- 该目录已被 `.gitignore` 排除，不应上传仓库。
- SubjectState、事件/变化记录、唤醒、思考、权限、学习和资源均有 JSON 持久化实现。
- ActionSession 当前只有内存仓储，进程重启后不恢复。
- Memory 只管理检索请求、相关性和影响记录，不拥有长期记忆存储。

### 接口与前端状态

- `APIService` 已提供统一请求/响应模型及状态、记忆、感知、思考、行动、唤醒和聊天入口。
- `ContinuityMCPAdapter` 与 `SkillAdapter` 是接口设计，不是已连接的平台集成。
- 本地 HTTP 服务和最小聊天界面可运行，但不是生产部署方案。
- 前端不保存 SubjectState、记忆或人格状态。
