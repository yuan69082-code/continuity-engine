## 当前核心闭环状态

工程总档案定义的目标实时闭环必须经过 Action Gate：

```text
PlatformObservation / 合法内部触发
→ Continuity Engine 读取 SubjectState、Memory 与允许使用的事实
→ Perception → Thinking
→ 模型结果返回 Continuity Engine 并继续进入 Thinking / Action
→ ActionDecision
   ├─ 未批准 UPDATE_STATE：不创建状态变更，revision 保持不变
   └─ 合法批准 UPDATE_STATE：内部 Event / StateMutation → Evolution → SubjectState，revision 按合法演化结果推进
```

SubjectState、revision、Event、StateMutation、Evolution 和最终主体表达继续由 Continuity Engine 权威控制。Vio 负责现实权限、安全确认、供应商路由、Token Budget、供应商执行和可信用量记录；供应商候选只能作为 CapabilityResult 返回原 operation/ThinkSession，再经 CapabilityResultInterpreter、Thinking、Action Gate 和 ReplyComposer 形成主体表达。模型文本不能直接成为 StateMutation，Vio 不能把原始候选直接保存为最终主体 Message；只有合法批准的 `UPDATE_STATE` 才能进入 Event/StateMutation/Evolution。首次 S4-Live 真实验证了该表达路径，并以 `changed=false`、revision 不变结束；真实模型触发 `UPDATE_STATE` 的演化路径仍未验证。
