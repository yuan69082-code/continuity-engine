## 实时状态闭环目标

```text
PlatformObservation / 合法内部触发
→ Continuity Engine 读取 SubjectState、Memory 与允许使用的事实
→ Perception → Thinking
→ 模型结果返回 Continuity Engine 并继续进入 Thinking / Action
→ ActionDecision
   ├─ 未批准 UPDATE_STATE：不创建状态变更，revision 保持不变
   └─ 合法批准 UPDATE_STATE：内部 Event / StateMutation → Evolution → SubjectState，revision 按合法演化结果推进
```

模型文本不能直接成为 StateMutation，模型回复不意味着状态必然变化；回复生成和状态演化是有关联但不强制绑定的两个结果。当前已完成闭环所需的状态、Memory 接口、Mutation/Event、Evolution、Action Gate、持久化框架和 Engine 侧 Capability 暂停—恢复协议核心；Vio V4、受控双方 S4 与首次 S4-Live 已验证外部候选回流原 Thinking/Action 的链路。首次真实试聊为 `changed=false`；真实模型触发合法 `UPDATE_STATE` 的演化路径仍未完成验收。

## 愿景驱动的正式运行形态（未来）

工程总档案将长期系统关系定义为：

```text
用户
  ↓
Vio 前端
  ↓
Vio 平台后端
  ↕  Continuity Integration Contract
Continuity Engine
  ↕  通过 Vio 管理的能力通道提出请求并接收结果
模型 / Tool / MCP / 设备
```

正式运行时，引擎应作为独立持续运行的核心服务，保持自己的进程、状态存储、时间系统、唤醒机制和接口，并通过正式版本化契约与 Vio 平台后端通信。二者是数据库独立、边界独立的平行系统；Vio 前端只连接 Vio 平台后端。外部能力结果必须返回引擎继续进入 Thinking / Action，但只有合法批准的 `UPDATE_STATE` 才能创建内部 Event/StateMutation 并经 Evolution 改变 SubjectState；否则 revision 保持不变。

## 工程总档案后续路线

下列阶段是工程总档案 v1.0 的推荐后续路线。部分固定本地受控基础和首次 S4-Live 单次验收已完成，但通用真实外部能力与生产形态仍为**未完成或待立项**，不能把受控验收或单次 S4-Live 扩写成日常使用或生产能力：

### 阶段 8：AI 模型接入

E5-A、Vio V4、受控 S4 和首次 S4-Live 已验证现实权限、安全确认、Provider 路由、Token Budget、真实单次执行事实和结果返回原 Thinking/Action 的边界。后续若获授权，应面向通用/日常使用或更多 Provider/故障场景继续验证；模型仍不接管主体身份或状态，只有 Action 合法批准 `UPDATE_STATE` 才进入内部 Event/StateMutation 与 Evolution。

### 阶段 9：MCP 与外部记忆库

在现有 Memory 管理接口和 ContinuityMCPAdapter 边界上连接真实长期记忆系统。当前没有真实 MCP 传输或外部长期记忆存储。

### 阶段 10：正式前端应用

Vio V5/F1 已完成固定本地受控 Conversation/Message 与前端接线，并通过共享验收；这不是面向一般用户的生产入口。生产阶段仍须保持 Vio 前端只连接 Vio 平台后端、Vio 与 Engine 数据库独立，并补齐生产认证、多租户、外网、部署和治理；Continuity Engine 始终是连续状态和 SubjectState 的唯一权威。

### 阶段 11：自主学习完善

在现有受控 Learning 框架上完善用户画像、技能学习、证据质量、审核和策略版本；不得演变为未经确认的自动永久人格修改。

### 阶段 12：自主运行

把引擎部署为具有独立进程、状态存储、时间系统、唤醒机制和受控接口的持续运行核心，在资源、权限和确认约束下形成可持续的 Wake → Perception → Thinking → Action 循环。远期可逐步支持时间/环境感知、自身兴趣与目标、内部思考和是否表达或行动的决定。后台调度、主动联系、外部执行以及与 Vio 平台后端的正式版本化契约连接当前均未实现。
