### 3.1 正式目录隔离哈希的可复现算法

当前权威验收证据统一使用项目内 `continuity_engine.testing.persistence.tree_inventory_hash`。该函数递归枚举 `.continuity-data` 的全部普通文件，按 POSIX 路径文本排序；每个条目只包含相对 POSIX 路径 `relativePath` 和带 `sha256:` 前缀的原始文件字节 SHA-256 `fileHash`；随后对完整条目数组执行 RFC 8785 JSON 规范化、UTF-8 编码和 SHA-256，输出 `sha256:` 加 64 位小写十六进制。可复现命令为：

```powershell
$env:PYTHONPATH = "src"
$env:PYTHONDONTWRITEBYTECODE = "1"
python -c "from pathlib import Path; from continuity_engine.testing.persistence import tree_inventory_hash; print(tree_inventory_hash(Path('.continuity-data'))); print(sum(1 for p in Path('.continuity-data').rglob('*') if p.is_file()))"
```

2026-08-27 证据收口的测试前后结果均为 `sha256:f9c710c6085e430a251f74463d57133f8c5a4497fe8ffa2ccb96be2db1037bb2`，文件数均为 7。

同日历史记录中的 `ba0cf60153368eaacd3ffe75b3afd5e0563c9e3ab5b8ea3b0fad97cb46986908` 已确认可稳定复算，但属于不同的独立外部聚合算法：递归纳入全部普通文件，按相对 POSIX 路径排序；依次向一个 SHA-256 聚合器写入“相对 POSIX 路径的 UTF-8 字节 + 单个 NUL 字节 + 文件原始内容 SHA-256 的 32 个原始摘要字节”。该算法不含绝对路径、文件长度、JSON、换行或 `sha256:` 前缀，最终输出 64 位小写十六进制。可复现命令为：

```powershell
$env:PYTHONDONTWRITEBYTECODE = "1"
python -c "from pathlib import Path; import hashlib; root=Path('.continuity-data'); files=sorted((p for p in root.rglob('*') if p.is_file()), key=lambda p:p.relative_to(root).as_posix()); h=hashlib.sha256(); [h.update((p.relative_to(root).as_posix()+'\0').encode('utf-8')+hashlib.sha256(p.read_bytes()).digest()) for p in files]; print(h.hexdigest()); print(len(files))"
```

该独立算法在同一轮测试前后均得到 `ba0cf60153368eaacd3ffe75b3afd5e0563c9e3ab5b8ea3b0fad97cb46986908`、7 个文件。两个结果来自不同序列化与聚合规则，不能互相替换，也不表示正式数据状态冲突；验收、矩阵和后续复核均以项目内 `tree_inventory_hash` 为当前权威证据。
