# 一条已经实跑的回答前链路

以下来自正式 `test_t03_raw_noon_and_afternoon_messages_recall_before_answer` 的实际受控TEST场景和断言；不是一段真实用户对话，也不是对真实模型回答质量的评判。原始运行状态见 [57项专项](w02-b-final-04.json) 和同名stderr；具体代码见[测试入口](../../../tests/test_w02_recall.py)。未编造一次额外运行或新的请求ID。

1. 在独立TEST根已有可追溯的旧进食Event：“我以前吃过螺蛳粉。”。
2. 测试可信时钟推进至同日12:00。原始消息“我中午12点吃过午饭。”走正常入站、感知与W02-A。该消息可临时参与本次沟通，不要求先被长期巩固。
3. 同日15:00收到原始消息“我又在吃螺蛳粉。”。自动回忆在本轮Thinking之前评估对象、进食报告、来源时间和不确定性，不依赖用户主动要求检索。
4. 原Router取得当前可读旧材料：旧进食根，以及12点消息的原operation引用；权限、版本和根状态仍须有效。关联只允许有依据的共同事件/新对象；没有新的关系、足够材料或预算耗尽就停。实际停止码、来源结果、检索量和时延保存在该请求的recall记录，不预填固定停止原因。
5. 原Composer完成去重、权威分层、冲突保留和预算裁剪。测试断言最终fragment中**同时存在12点旧消息与旧进食材料**，当前fragment为15点，相差3小时；Provider实际收到的就是这个最终Context，说明不是先答后查。
6. Context保留 `HUNGER_NOT_DETERMINED`，注明来源时间不能证明实际事件时间。它可以帮助主体联系上下文，但不能把“可能馋了”升级成“确定不饿”，也不能强迫主体说出召回材料。

同样经过真实入站的负对照包括：“不爱吃”“朋友在吃”“想吃但没吃”“去年吃过”、同义及“螺丝粉”变体；引用、问题和不可靠否定保留不确定性。候选偏好另由原独立Event根及可配置规则形成，仍是未确认DerivedSummary，不是长期人格或主体事实。

## 怎样检查现有请求

在已装配自动回忆的同一Engine实例调用：

```python
view = app.adapter.service.recall_outcome(request_id)
```

返回的是原准备记录和当前可验证状态；READY不等于表达/现实行动已成功，总流程完成另看返回信息。BLOCKED保留本次准备失败原因；查询不恢复执行，不触发模型、回忆、学习或revision。当前权限撤销、内容损坏、身份不符或旧Context过期时拒绝，而不是展示未经核验的旧材料。

独立TEST跨进程 `prepare → resume → show` 的运行方法见[实现说明](implementation-notes.md)。正式组合测试验证一次效果返回丢失后，新进程沿原请求恢复，累计效果和扣费仍各一次；show前后数据树不变。不要把TEST根改为正式数据目录。

时间口径：用例使用Engine隔离Fixture的可信冻结UTC时钟，受控同日12:00与15:00相差3小时；没有读取正式主体、冒用本机墙钟或把报告接收时间当作真实进食已发生的证明。
