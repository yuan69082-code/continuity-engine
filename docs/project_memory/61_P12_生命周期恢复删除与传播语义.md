## 三个独立维度

| 维度 | 含义 | P12 行为 |
|---|---|---|
| `MemoryStatus` | ACTIVE / CORRECTED / REVOKED / DELETED，既有事实/来源有效性 | 纠错、撤销不能由恢复命令抹掉；保留 P04 枚举与来源 Event lineage |
| `MemoryTemperature` | HOT / WARM / COLD / ARCHIVED，既有热度 | 保留旧策略与序列化。温度不冒充新的生命周期状态 |
| `MemoryLifecycle` | active / inactive / archived / deleted，可消费性 | 独立字段。旧记录没有此字段，不迁移、不改变旧 canonical hash |

旧 ACTIVE 状态且温度未归档映射 active；旧温度 ARCHIVED 映射 archived；旧 CORRECTED/REVOKED 映射 inactive 但不可恢复；旧 DELETED 映射 deleted。低层 `list_memories` 保留旧温度枚举行为，普通 RepositoryMemoryRetriever、Router 和 exact Resolver 按可消费性排除归档。新显式生命周期优先于旧温度映射，因此经授权的恢复可以保持温度历史，同时重新参与普通检索。

合法显式转换：active → inactive；active/inactive → archived；inactive/archived → active；未终结的有效记忆 → deleted（仅 TEST 开放）。deleted 不可恢复、不接受后续 revision。已纠错/撤销的条目不能通过生命周期恢复。停用不表示原事实变假，也不自动撤销已经形成的 SubjectState 判断。

## 命令、权限与单一事务

[命令类型](../../src/continuity_engine/domain/memory_lifecycle.py) 绑定 command ID、subject/environment、目标 Memory、expected revision/hash、scope、permission ID/revision、时间窗、理由、确认 ID 和来源快照。确认 Port 必须核实完整命令，不接受单个裸布尔开关替代来源绑定；本阶段 Fixture 中的确认注册表是显式 TEST 输入，不是生产鉴权系统。

[LifecycleService](../../src/continuity_engine/services/memory_lifecycle_service.py) 在写事务内检查当前权限和确认；在可能耗时的确认/来源调用之后再次检查权限及可信时钟。失效命令失败关闭。恢复、降权、衰减还核对当前 raw source hash 和传递 Memory 版本。来源 Port 无法证明有效时不能恢复；内置 TimelineMemorySources 适配当前 Event/Memory，外部 Message 的生产来源未接入，需要未来显式可信 Port，不能靠同名字符串通过。

所有 lifecycle 输入/结果绑定追加到已有 `lineage_records`，Memory 新版本和依赖摘要失效在同一个 JSON 文档原子替换。P12 使用独立内部 `MemoryLifecycleSignal`，不扩充旧纠错/撤销/删除枚举的遍历语义。没有第二个操作账本、Memory Store 或 SubjectState。并发保证限定本机同进程的完整读—校验—追加—替换锁，覆盖不同 repository 实例的线程；不宣称跨进程并行写入或分布式事务。跨进程串行重启读取和重放另有实测。

重复 command ID、同输入只返回当前状态回执，不推进 revision；同 ID 不同输入明确冲突。旧归档命令在后来删除后重放只能报告当前 deleted。历史事实回执不是新的材料授权；恢复当前内容始终要求当前授权。历史 P04 consolidation 仍可精确重放原 revision/hash；过时/撤销回执带 `historical_only`，不得作为新 consolidation 输入；deleted 和显式停用材料不能用旧请求重新提供为当前材料。

## 实际衰减与降权

没有正式默认遗忘阈值、归档年限、定时器或自动清理。`ForgettingPolicy(policy_id, half_life_seconds)` 必须由调用方显式注入有限正值。确定性计算为 `new_weight = old_weight * 2 ** (-elapsed_seconds / half_life_seconds)`，以最近权重时间或原 consolidated_at 为起点；主动降权乘明确的 `[0,1)` factor。可信时钟倒退拒绝，同一时点再次衰减不重复扣权；同一请求重放零写入。输出保留策略、时间、输入/结果 hash 及理由，可审计计算过程。

原证据 confidence 不被重写成“事实变假”。权重实际作用于普通 Memory 检索、Router relevance/importance/activation、Composer 可消费置信度以及重建 Summary 的来源权重。摘要权重由当前来源计算，不建立摘要事实权威或重复持久索引。在正常 C1 中，同根 Timeline 材料也受召回权重/排除约束，避免用普通 raw Event 召回绕回旧材料；Timeline 权威历史、客观时间戳及显式审计读取原样保留。未配置 Memory gate 的旧 Timeline 路径保留原 hash/读取行为。

显式 restore 经当前权限与来源核实后将可消费权重恢复为 1，并保存新的版本和权重时间。原衰减/归档版本继续存在；不会自动恢复旧 Context、旧摘要或旧 Learning 验证。

## 来源传播与合法后续使用

停用、归档、降权、恢复、删除均使依赖摘要追加 INVALIDATED 版本；只在来源重新可用时显式重建。新子记忆密封 source_memory_bindings；父记忆版本变化使旧子版本不可消费，恢复父记忆不静默恢复旧子版本。旧未绑定子记录遇到父 P12 生命周期变动失败关闭。新来源完整绑定仍支持 R07 部分根证据合并，不丢旧根、不重复计算根。

普通检索不能通过换新 Memory ID/Consolidation ID 再次引入停用或删除证据。仓储写事务再次检查此边界。新独立 Event 仍能形成新记忆；不因一个停用条目禁止整个主体继续学习。

Router 重新验证来源窗口/版本；Composer exact resolver 重新验证当前可用性/版本/hash；C1 的原 Context current 检查阻断旧片段。C1 已处理 Event 集合包含 inactive/deleted 记录，重启不会再次把原 Event 自动 consolidated 成活跃记忆。关闭 Memory feature gate 时不调用生命周期入口或新增读取。

Learning 在原候选历史中密封来自当前 Memory 的 subject/environment/revision/hash/根绑定；validate 与 solidify 都重查，支持被停用、撤销、删去、降权或版本变化时拒绝旧验证。保留 R05/R06 已验收的置信度公式、目标自身与聚合置信度区分、用户确认和合法重启固化。新绑定缺失不能降级 legacy；真正旧的无版本外部 Memory port 仍遵循原规则，若本地已有该 Memory，则仍检查当前可用性。Learning 只返回原有 Evolution proposal，不能直接推进 SubjectState/revision。先前合法主体判断不会因遗忘被自动改写。

## 历史召回与删除的准确范围

`trace` 要求当前权限，仅返回结构、根、版本及 lineage ID，不返回正文。历史召回要求当前精确权限、有效来源、至少两个全部匹配的强相关词，limit 为 1—5；稳定排序，结果标识 HISTORY_ONLY/restored=false。它不自动参与普通 Thinking，也不产生 restore 命令；需要再次使用时必须显式恢复、重新 Router/Composer。

TEST 的 delete 是不可恢复的逻辑 tombstone，正常检索、旧请求、换 ID 及重启不得使其重新可用；原 Memory 文本仍留在追加式审计文件，**没有物理永久擦除**。正式删除、备份清除、灾难恢复属于 NOT_READY 的 P20/P21 范围。P12 TEST 删除不会调用 Event 删除，不触碰正式数据。正式策略与确认方式仍待用户决定。

Fixture 在任何初始化前复用已复核的 P08 Temp/受保护路径/Windows 大小写/链接检查。拒绝路径检查完整文件字节不变、没有新目录、没有唤醒/通知/资源账本变化。新链接传感器测试使用受控检测；真实链接权限相关覆盖沿用原测试，既有 1314 SKIP 不计 PASS。

长期证据包含独立 7 日权重/归档/恢复/删除 Golden，以及 30 个逻辑日、12 个新事件、6 次正常 Engine 交互、2 次 runtime 重开、候选/Context 预算和文件体积观察。另有真实新 Python 进程读取 deleted 回执、重放零写入测试。长期场景不是三轮全量，也不宣称生产持久常驻运行。
