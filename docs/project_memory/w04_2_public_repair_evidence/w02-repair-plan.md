## 已测到什么

recall-profile-02五项原用例各一次原断言通过；14/11项的旧失败不能改写为新通过。D-084操作日志作用域为真，15次日志读取只做1次全量校验；能力账本30次读取耗时约26ms，非复用失效。第三轮原场景本次prepare约804ms，Router512ms/Composer248ms；五次external_items累计378ms，均仍做当前权限、回执、根复核。嵌套时间不相加。

recall-cpu-01为另行声明的两个用例各一次CPU剖析，两个ERROR均RECALL_TIMEOUT（有明显观察开销），不冒充无插桩性能。第三轮：外部注册仓储_read108次/451.617ms，其中_safe108次/338.007ms；每条路径及各祖先依次is_symlink、exists、is_junction，反复查询同一文件元数据。整体1836次is_symlink、1989次exists、1836次is_junction。这是已定位的重复I/O放大机制，不是“D-084失效”，也不足以唯一解释旧现场瞬时耗时变化。

## 最小修改及公共影响

仅拟改 src/continuity_engine/storage/json_external_provider_repository.py 的_safe：每次访问仍重新检查目标及全部祖先；同一个路径用一次不跟随链接的lstat读取类型/Windows reparse tag，同时判定软链接及目录连接。无缓存、无跨请求授权复用，不删当前路径检查，不改变注册/回执/来源/材料/摘要核验。路径不存在仍允许后续原逻辑处理，真实权限错误不绕过。保持读取/解析和原返回副本逻辑不变，不扩写其他模块。

调用方为P16注册/缓存读取、W02-C当前根校验和W02 Router/Composer；W04-2沿原链复用，原head同一仓储代码已有此重复路径。W04三个已改公共入口在回忆内只有ActionSpecification校验分支被调用，前轮原/current计数均18；本次未证明该分支绝对零开销，不把旧版复现替代新影响分析。后续原五场景、W04专项、兼容和全量同版验证仍必需。
