## 2. Event / Evolution

### Event

**作用：** 使用统一事件模型描述发生了什么，包括 occurred/observed/recorded 三时间、时间依据、分类、具体来源与来源类别、内部/来源/关联身份、证据、因果/修正/撤销引用、内容、影响范围、StateMutation、原因和 metadata。

**输入：** occurred_at、可选 observed_at/recorded_at、source/source_kind、event_type/classification、eventId/sourceEventId/correlationId、证据/引用、content、impact_scope、mutations 和 reason。

**输出：** 可序列化、可持久化并可交给 Evolution 的 Event。

### Evolution

**作用：** 按固定字段规则应用 Event，校验影响范围和变更类型，生成状态变化及完整审计记录。

**输入：** 当前 SubjectState、Event 和服务层提供的 expected_revision。

**输出：** StateEvolutionResult，包括新 SubjectState 和 StateUpdateRecord。StateUpdateRecord 保存 Event、before/after revision、逐字段 before/after 差异和变化原因。

**核心文件：**

- `domain/events.py`
- `domain/evolution.py`
- `services/subject_state_service.py`
- `services/action_evolution_service.py`
- `domain/timeline.py`
- `services/timeline_service.py`
- `storage/json_repository.py`
- `tests/test_evolution.py`
- `tests/test_event_persistence.py`
- `tests/test_p03_event_semantics.py`
- `tests/test_p03_timeline.py`

**当前状态：P03 已于 2026-08-30 正式验收。** 原 Event/StateUpdateRecord 持久化权威保持不变；精确重复幂等、冲突重复失败、写入顺序引用门、历史分类 mutation 门、追加式 correction/revocation、三时间 UTC 语义和重启/回退时钟恢复均有实现、测试和验收。Timeline 是从同一历史重建的只读投影，没有写入权或第二事实存储。

### 实时状态闭环边界

工程总档案定义的目标闭环必须经过 Action Gate：PlatformObservation 或合法内部触发 → SubjectState/Memory/允许事实 → Perception → Thinking → 模型结果返回引擎 → Thinking/Action → ActionDecision。未批准 `UPDATE_STATE` 时不创建状态变化且 revision 保持不变；只有合法批准的 `UPDATE_STATE` 才能创建内部 Event/StateMutation 并经 Evolution 更新 SubjectState。当前已经完成状态读取/保存、Memory 管理接口、StateMutation/Event、Evolution、Action 决策边界、审计框架和 Engine 侧 Capability 暂停—恢复协议核心；Vio V4、受控 S4 与首次 S4-Live 已验证现实执行分层和结果回流。首次真实试聊为 `changed=false`，尚未验证真实模型触发 `UPDATE_STATE` 的演化路径。
