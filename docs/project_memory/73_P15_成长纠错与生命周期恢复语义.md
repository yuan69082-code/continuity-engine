# P15 成长、纠错与生命周期恢复语义

## R1/R2/R3 当前恢复规则（覆盖下方初版说明中的缺口）

生命周期旧格式兼容仅适用于从未引入受管理生命周期历史的记录。仓储在读取及写入前从原Evolution更新链核对命令、主体、环境、Owner、稳定Event身份、before/after、revision和合法转换，并将最后生命周期值与当前值比较。已有历史时字段丢失、旧ACTIVE片段或DELETED回退均拒绝，不自动修复。普通同名旧Event不是管理历史。生命周期时间保持命令下界及自身历史单调性，不强制不同Port时钟与Evolution applied_at额外排序。

P15学习在Evolution前仅为GROWTH_PREPARED：SOLIDIFY的待提交Trait不活跃；ROLLBACK在实际提交前保留已存在Trait贡献。实际是否形成或移除人格只查询原Evolution事实，核对完整Event、revision、update变化及授权绑定；COMMITTED摘要或hash不能替代原事实。已提交后中断可完成原Learning审计而不再推进主体revision，后来的撤权不抹去原事实。

未提交旧命令仍绑定原revision，不能覆盖后来无关变化。新的同操作、同主体/环境/Owner、当前有效确认可以先重查权限、来源和支持，再在原Learning历史追加绑定原准备记录hash及替代命令的SUPERSEDED记录，随后在当前revision准备新Event。原命令/失败/后来变化保留，已终止原命令不可重放为新执行。终止后中断允许按同一替代命令继续；不同内容同身份拒绝。旧P15提前标记CONSOLIDATED/REVOKED的待提交记录也先查询事实；只对仍未提交且未被后来实质证据记录覆盖的准备状态闭合，不重写旧记录。未新增请求账本。

SOLIDIFY在新确认及提交前保留当前来源、独立根、支持状态和合法置信度公式重验，变化后的证据不偷偷替换原准备Event。ROLLBACK用于移除实际旧贡献，不要求已失效支持重新变真。正式隐私、归档和删除策略仍NOT_READY。

read_growth返回前再次读取主体状态并比较完整hash和可见性/身份绑定，再检查当前Permission及export权限。读取途中撤权、EXPIRED、状态改变或export许可丢失均拒绝详情，观察自身零写入；可见性不改变内部心智。这里沿用现有EXPIRED状态机制，不新增正式权限时长政策。

IMPLEMENTED_NOT_ACCEPTED；等待独立复核。原SubjectState/Event/Evolution仍为权威；以下为当前实现语义，最终验证以[测试入口](74_P15_测试索引与验收入口.md)为准。[Stage Brief](71_P15_人格关系学习与主体生命周期架构边界.md)。

## 成长链

正常 C1 的可消费 Timeline/Memory 来源中，只有带明确学习注解的经历进入原 LearningService；不是把任意 Provider 句子变成人格。候选保存精确来源 reference、版本/hash、根、原事件 hash。验证/固化重读当前来源权限、P12 可消费性、Timeline 状态和根身份；派生摘要不成为新独立根。验证和当前固化使用原 R05/R06 已验收公式，不采用另一种平均数政策。

显式确认的固化/纠错经过原 ActionService 局部门禁和 Evolution。新增恢复字段附于原 LearningRecord，不建立请求账本：保存原 command/principal 绑定及完整待提交 Event。Learning/PersonalityTrait 是证据及提案索引，实际人格是否变化以 SubjectState/Evolution 为准。中断在 LearningRecord 后、Evolution 前时，重启先核实原记录；未提交的新变化必须重查当前来源、确认、版本和权限。已提交的原 Event 则核实完整绑定后恢复事实，不因后来的撤权重复提交或抹去历史。

撤销只 REMOVE 本条 Trait 的贡献，保留后来无关条目；不是把 P01 旧快照覆盖到当前主体。旧记录无 P15 字段保持旧格式；新记录缺少当前来源验证器时失败关闭。

## 关系、叙事、意志

现有 SubjectState 扩展 `identity.self_narrative` 和 `relationship.objects` 两种强类型内部值。内容来自真实 C1/P14 的当前经历理解，仍是主观解释；含稳定对象/条目身份、来源根、版本、时间。正常 Thinking 的内部 processor 生成提案，再由 Action/Evolution 提交。Provider 输入入口继续拒绝直接提供这些字段；其他人格字段的 Thinking 直接写入限制保留。

对象关系的多种立场与 P14 LOVE/HATE、Desire、Will、Conflict 共存，未按“友好”选赢家。叙事重新理解保留原来源和 Evolution 历史，Event 不改写。获准 Context 使用有界投影和完整状态 hash；明文不进入结构 Trace。长期 Will 继续使用 P14 desire identity 和轨迹，不另建优先级/意志系统。

成长观察复用原 Owner 身份与 PermissionService。关系范围必须显式配置；未配置返回 `GROWTH_VISIBILITY_POLICY_NOT_READY`。详细与摘要观察只读，不能借可见性策略改变内部心智；没有生产认证或隐藏推理采集。

## 生命周期

旧 SubjectState 无 lifecycle 字段时映射 ACTIVE，序列化不静默补写。新管理 CREATE 连同首条 Evolution 原子创建；ACTIVATE 后可 SUSPEND，暂停可 RESUME，显式策略允许 ARCHIVE/RESUME。DELETED 为终态。状态仍位于原 SubjectState，命令身份与审计位于原 Event；不新增生命周期操作账本。

Owner 命令必须经过可信宿主身份/确认 Port、当前 Action 权限、subject/environment 和 revision 检查。SUBJECT 的 SUSPEND_INTENT/ARCHIVE_INTENT 只追加非状态变更的意图 Event，不等于执行暂停、归档或删除。管理原请求重放只恢复原事实，不重新授权或重置当前状态。

新 C1、Thinking、Awakening、ResourceAwareWakeScheduler 与接好 SubjectState Port 的 Scheduler 在新执行前检查活跃状态。UNKNOWN 查询及已提交事实恢复保留；新模型执行和 NOT_EXECUTED 后执行仍须当前活跃/原 C1 检查，不能把保存的 attempt 当成永久许可。静默/资源/现实边界原有门禁不取消。

内部 TEST Host Selection Port 只保存宿主选择指针，不改变 SubjectState revision，也不改冻结的外部 SubjectBinding。解绑与停止会话不是暂停主体，更不是账号删除。新 Genesis 不复制旧主体人格、私人记忆、关系、Learning 或 Mind。TEST 显式迁移仅支持双端确认且版本/hash 匹配的 PUBLIC_OBSERVATION；进入目标为非权威 Observation，不导入人格/情绪/关系或旧主体权威。

## 未开放能力

正式归档政策、删除保留/恢复窗口、关系可见性仍待用户决定。默认策略未配置；独立 TEST 可注入归档和逻辑删除参数，删除保留时长从可信实际转换时间计算，不能靠回填命令时间缩短。DELETED 禁止重新激活，但文件和历史保留；没有声称物理擦除、备份清除或生产永久删除。P01 Snapshot/Branch 仍仅 TEST/Research，不能替代生产主体恢复。无 Assistant/Vio、真实 Provider/Adapter、后台常驻、P16—P23 或 Git 写操作。
