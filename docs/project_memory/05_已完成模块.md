# 已完成模块

> 核心文件路径均相对于 `src/continuity_engine/`。状态口径：**已完成**表示当前 v0.1 核心实现和测试存在；**部分完成**表示内部结构已存在但统一入口、持久化或真实集成仍有缺口；**未实现/未来规划**表示当前只有边界设计或计划。

工程总档案 v1.0 将当前阶段概括为“底层连续性引擎原型完成”。本文件中的 SubjectState、Evolution、Memory、Awakening、Perception、Thinking、Action、Permission、Learning 和 Resource 均已建立 v0.1 内部框架；其中标为“部分完成”的模块缺少真实外部接入、统一入口或完整持久化，不能按最终产品能力理解。

## 1. SubjectState

**作用：** 表达主体当前连续状态，是整个引擎的中心状态对象。通过 revision 标识状态版本，并以 JSON 跨进程保存。

**输入：** subject_id、初始主体资料或持久化状态文档。

**输出：** SubjectState 快照和当前 revision。

**核心结构：**

- `identity`
- `relationship`
- `continuity`
- `temporal`
- `intentions`
- `emotion_state`

**核心文件：**

- `domain/models.py`
- `services/subject_state_service.py`
- `storage/base.py`
- `storage/json_repository.py`
- `tests/test_models.py`
- `tests/test_repository.py`
- `tests/test_service.py`

**当前状态：已完成。** 六个状态分区、模型校验、revision、JSON 持久化和重启恢复均存在。生产数据库、跨版本迁移工具和分布式并发控制未实现。

## 2. Event / Evolution

### Event

**作用：** 使用统一事件模型描述发生了什么，包括时间、来源、类型、内容、影响范围、StateMutation、原因和 metadata。

**输入：** occurred_at、source、event_type、content、impact_scope、mutations 和 reason。

**输出：** 可序列化、可持久化并可交给 Evolution 的 Event。

### Evolution

**作用：** 按固定字段规则应用 Event，校验影响范围和变更类型，生成状态变化及完整审计记录。

**输入：** 当前 SubjectState、Event 和服务层提供的 expected_revision。

**输出：** StateEvolutionResult，包括新 SubjectState 和 StateUpdateRecord。StateUpdateRecord 保存 Event、before/after revision、逐字段 before/after 差异和变化原因。

**核心文件：**

- `domain/events.py`
- `domain/evolution.py`
- `services/subject_state_service.py`
- `storage/json_repository.py`
- `tests/test_evolution.py`
- `tests/test_event_persistence.py`

**当前状态：已完成核心模块。** Event 模型、状态变化规则、before/after 差异、expected_revision 校验、StateUpdateRecord、重复事件保护和重启恢复均有实现与测试。

### 实时状态闭环边界

工程总档案定义的目标闭环为：用户输入 → SubjectState 读取 → Memory 检索 → 模型回复 → StateMutation → Evolution → SubjectState 保存。当前已经完成状态读取/保存、Memory 管理接口、StateMutation/Event、Evolution 和审计框架；真实模型回复以及模型调用前后自动串联整条闭环尚未完成。

## 3. Memory

**作用：** 管理记忆检索请求、候选相关性、检索结果和记忆对当前上下文的影响记录，不负责长期保存记忆正文。

**输入：** subject_id、当前查询/关注、状态上下文、候选数量限制，以及可插拔 MemoryRetriever 返回的候选。

**输出：** MemoryRetrievalResult、排序/过滤后的相关记忆和 MemoryInfluenceRecord。

**核心文件：**

- `domain/memory.py`
- `services/memory_ports.py`
- `services/memory_service.py`
- `tests/test_memory_service.py`

**当前状态：框架完成，真实接入未完成（总体为部分完成）。** 已完成 MemoryRetrievalRequest、候选、相关性判断、MemoryRetrievalResult、MemoryRetriever/MemoryInfluenceRecorder 接口和影响记录规则。未完成外部长期记忆库、MCP 接入、真实数据库存储；测试使用确定性替身。

## 4. Awakening

**作用：** 建立自主运行的会话起点。支持手动和定时唤醒，读取当前状态、最近演化和相关记忆，生成 WakeContext 与 WakeDecision。

**输入：** 唤醒原因、subject_id、当前时间、状态仓储、近期事件/变化和 MemoryService。

**输出：** WakeSession、WakeContext、AwakeningResult，以及 SLEEP、THINK、CHECK_MEMORY、READY 四类决策。

**核心文件：**

- `domain/awakening.py`
- `domain/awakening_rules.py`
- `services/awakening_service.py`
- `storage/json_awakening_repository.py`
- `services/resource_aware_wake_scheduler.py`
- `tests/test_awakening.py`
- `tests/test_resources.py`

**当前状态：框架完成，真实自主运行未完成（总体为部分完成）。** AwakeCycle、WakeSession、WakeContext、确定性决策、JSON 日志和单次手动/定时/事件唤醒已完成。没有常驻进程、真实后台调度器或主动联系用户；AwakeningService 的直接入口尚未全部强制经过 ResourceManager。

## 5. Perception

**作用：** 把主体状态、时间、关系、记忆和事件转为“当前感受到什么”的统一观察层，并成为 Thinking 的唯一直接输入来源。

**输入：** SubjectState、WakeContext 派生信息、MemoryRetrievalResult、RecentEvents 和 CurrentTime；由上层组装，不直接访问数据库。

**输出：** PerceptionResult，包括 Current Focus、Temporal Perception、Relationship Perception、Memory Influence、Observation、Internal Drive 和 Summary。

**核心文件：**

- `domain/perception.py`
- `domain/perception_rules.py`
- `services/perception_service.py`
- `tests/test_perception.py`

**当前状态：已完成。** v0.1 确定性感知模型、规则、序列化和只读保护均有测试。不含 AI 或情绪模拟，Perception 无权修改 SubjectState。

## 6. Thinking

**作用：** 将感知结果转为标准化内部思考结果，记录 ThinkSession，并通过 Provider 接口为未来模型调用预留替换点。

**输入：** PerceptionResult；Thinking Engine 不直接读取数据库，TokenBudget 由预算管理接口分配。

**输出：** ThinkingResult 和 ThinkSession。Thinking 接收 PerceptionResult，通过 ThinkSession 保存上下文摘要、预算、结果、WakeSession/Perception 关联、状态写回引用和错误摘要。

**核心文件：**

- `domain/thinking.py`
- `services/thinking_ports.py`
- `services/thinking_service.py`
- `storage/json_thinking_repository.py`
- `tests/test_thinking.py`

**当前状态：框架完成，真实模型未接入（总体为部分完成）。** ThinkSession、ThinkingResult、Provider 协议、预算接口、JSON 会话和摘要日志完成。没有真实 GPT、Claude 或本地模型调用；不自动统计真实 Token，不保存完整思维链。

## 7. Action

**作用：** 把 ThinkingResult 中的行动倾向转换为受权限、风险、资源和 revision 约束的行动决定与计划。只规划，不执行。

**输入：** ActionContext，包括 subject_id、wake_session_id、think_session_id、subject_state_revision、ThinkingResult、感知摘要、当前时间、权限和资源限制。

**输出：** ActionIntent、PermissionCheck、RiskAssessment、ResourceAssessment、ActionDecision、ActionPlan 和 ActionSession；仅批准的 UPDATE_STATE 可进一步生成 Event。

**支持类型：**

- `NO_ACTION`
- `UPDATE_STATE`
- `REQUEST_MEMORY`
- `CONTACT_USER`
- `USE_TOOL`
- `DEFER`
- `REQUEST_MORE_THINKING`

**核心文件：**

- `domain/action.py`
- `services/action_ports.py`
- `services/action_permissions.py`
- `services/action_evaluators.py`
- `services/action_service.py`
- `services/wake_perception_thinking_action_service.py`
- `storage/in_memory_action_repository.py`
- `tests/test_action.py`

**当前状态：已完成决策规划层。** 权限/风险/资源/revision 路径有测试。ActionPlan 只会是 PLANNED、BLOCKED、DEFERRED 或 REJECTED；不存在真实 EXECUTED。ActionSession 当前只在内存中保存；Execution Engine 是未实现的未来独立模块。

## 8. Permission

**作用：** 记录主体长期拥有的权限、授权范围、能力、状态和变化历史，并向 Action 等模块提供 PermissionContext。

**输入：** 权限创建资料、状态变化/撤销请求、来源、原因和当前时间。

**输出：** PermissionState、PermissionChangeRecord、PermissionContext、能力检查结果，以及可选的权限变化 Event。

**状态：**

- `ACTIVE`
- `REVOKED`
- `LIMITED`
- `EXPIRED`

**核心文件：**

- `domain/permissions.py`
- `services/permission_service.py`
- `storage/json_permission_repository.py`
- `tests/test_permissions.py`
- `services/action_permissions.py`

**当前状态：已完成内部权限连续状态层。** 支持创建、查询、限制、撤销、历史、能力检查和重启恢复。没有手机、浏览器、邮箱、日历或其他真实平台权限接入。

## 9. Learning

**作用：** 把长期经历转为可验证、可固化、可回滚的长期特征候选；不是训练 AI 模型。

**输入：** LearningContext，包括 SubjectState、RecentEvents、MemoryInfluenceRecord、PerceptionResult 和 ThinkingResult；以及经历证据、验证和确认操作。

**输出：** LearningEvent、PersonalityTrait、LearningRecord、学习候选、建议变化、置信度，以及经批准后交给 Evolution 的 Event。

**核心流程：**

```text
经历 → 观察 → 假设 → 多次独立证据 → 验证 → 明确确认 → 固化
                                               ↓
                                           可回滚
```

**核心文件：**

- `domain/learning.py`
- `services/learning_service.py`
- `storage/json_learning_repository.py`
- `tests/test_learning.py`

**当前状态：框架完成，自主学习完善未完成（总体为部分完成）。** 规则型受控学习框架完成。单次事件不固化，当前实现要求至少三份独立一致证据并达到 0.75 置信度阈值；未验证学习仅是候选，固化和回滚生成交给 Evolution 的 Event。没有自动用户行为分析、模型训练、统一学习→Evolution 事务编排或无确认的永久人格改变。

## 10. Resource Management

**作用：** 统一管理主动运行时的 Token 预算、计算预算、运行模式、资源申请、使用记录和降级/延迟策略。

**输入：** subject_id、任务类型、预估成本、请求深度/模式、当前 ResourceState。

**输出：** 资源允许/拒绝/降级/延迟决定、更新后的 ResourceState 和 TokenUsageRecord。

**运行模式：**

- `LOW_FREQUENCY`
- `SCHEDULED`
- `CONTINUOUS`
- `DEEP_THINKING`

**核心文件：**

- `domain/resources.py`
- `domain/resource_policy.py`
- `services/resource_manager.py`
- `services/resource_aware_wake_scheduler.py`
- `storage/json_resource_repository.py`
- `tests/test_resources.py`

**当前状态：框架完成，真实计量未接入（总体为部分完成）。** ResourceState、ResourceManager、ResourcePolicy、资源检查入口、确定性预算、10% 保留策略及 JSON 历史已完成；Thinking、Learning、Wake 和外部接口存在资源感知连接点。但尚未实现所有路径强制经过统一资源入口，也没有真实模型 Token 自动统计、云资源计量、购买或支付。
