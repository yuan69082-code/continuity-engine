## 架构定位

P08 加法式路径：sealed P06 Context + trusted Thinking choice → Direct 或 Optional Plan → existing CapabilityCoordinationService / 同一 capability ledger → ActionService 本地 Permission/Risk/Resource gate → Recoverability / Reality Boundary → TEST Fake Adapter → exact receipt → 对应 Action/Step。旧 model.generate → 原 ThinkSession 路径不变。Plan 只保存结构，不成为第二执行事实；不改 SubjectState/Event/Evolution Authority，不提前建设 P09/P17。

P08 监工返修明确三层边界：repository 的结构/hash 验证不证明执行；同一 coordination 每次消费历史执行成功/失败必须独立核实 receipt；无回执 EXPIRED 必须 query 明确 NOT_EXECUTED，不以本地时间或 reason 充当执行事实。查询 UNKNOWN/异常保持未核实；停止记录与真实执行冲突拒绝消费、不覆盖历史。Action/Step 新执行仍需当前 Context 与完整执行门；过期 Context/choice 下只允许严格原身份的已发生事实恢复，不授权新动作。原账本、格式和模型类型恢复未重构，详见 [P08 恢复语义](45_P08_DirectPlanner执行恢复语义.md)。

Continuity Engine 是位于 AI 模型之外的连续性层。十个核心模块共同维护主体状态、变化原因、上下文理解、行动约束、长期演化和运行资源；它们不负责把某个具体 GPT、Claude 或本地模型固化进核心。

十层不是简单的单向调用栈。`SubjectState` 是中心状态，`Evolution` 是正式状态写入入口；Memory、Awakening、Perception、Thinking 和 Action 形成观察与决策链，Permission 和 Resource 提供约束，Learning 通过证据生成需要交给 Evolution 的变化建议。

```text
PlatformObservation / 合法内部触发 / Wake
        ↓
Memory → Perception → Thinking → Action
                     │           │
                     │           └─ Approved UPDATE_STATE
                     │                         ↓
                     └──────────────── Event / StateMutation
                                               ↓
Permission ────────约束───────────────→ Evolution ←──── Learning
Resource ─────────资源约束────────────→    ↓
                                        SubjectState
```

正式状态变化必须经过 `Event / StateMutation → Evolution → SubjectState`。Perception、Thinking、Action、Permission 和 Learning 均不得绕过该入口直接修改 SubjectState。

P00 新增的是全周期工程治理与证据层，不是第十一层主体能力，也没有修改本图中的任何运行关系。P00 冻结的唯一现实行动链、Reality Boundary 和 P01—P23 入口见 [11_P00_全周期能力与阶段基线.md](11_P00_全周期能力与阶段基线.md) 与 [14_P00_风险回滚与用户决策入口.md](14_P00_风险回滚与用户决策入口.md)。

**当前状态：已完成。**

**当前作用：** 保存主体当前连续状态和 revision，是整个引擎的中心状态对象。当前包含 identity、relationship、continuity、temporal、intentions 和 emotion_state 六个状态分区，并支持领域校验、JSON 持久化和重启恢复。

**未来扩展方向：** 建立统一 schema 版本与迁移工具、备份恢复、生产级仓储、跨进程并发控制和更完整的多主体隔离。扩展字段时必须保持兼容迁移，不能无依据重置连续状态。

## 2. Evolution 状态演化系统

**当前状态：已完成。**

**当前作用：** 作为 SubjectState 的唯一正式变化入口，接收 Event/StateMutation，校验 expected_revision 和影响范围，应用确定性变化规则，并生成包含 before/after 差异和原因的 StateUpdateRecord。P03 把 Event 扩展为包含三时间、分类/来源/证据、稳定身份与追加式引用的客观历史；相同 eventId/body 精确幂等，冲突正文失败关闭。FACT、OBSERVATION、INTENTION、CORRECTION、REVOCATION 无论是否迟到均不得携带 mutation；新显式 StateMutation 只属于 Action Gate 产生的 STATE_CHANGE。显式 recordedAt 还必须不晚于单次读取的 appliedAt。

**未来扩展方向：** 完善状态规则版本化、跨模块事务编排、冲突处理、迁移审计和更丰富的演化策略。未来模型或执行结果必须先返回 Thinking / Action；只有 Action 合法批准 `UPDATE_STATE`，引擎才能创建 Event/StateMutation，外部结果不能直接写入 SubjectState。

### Timeline 只读时间投影（P03）

**当前状态：已验收。** Timeline 只读取 Event/StateUpdateRecord 历史，按 occurredAt → observedAt → recordedAt → eventId 重建 UTC 投影，支持范围、first/last、间距、链和来源/分类/correlation 过滤。它没有持久化或修改接口，不是第十一层主体能力，也不是第二 Event Store。修正/撤销状态只在投影中派生，不反写历史。

### P06 Context Composer（已验收）

**当前状态：** 用户于 2026-09-03 正式验收 P06；P06、P06 Engine side 与 P06-01—P06-12 均为 `ACCEPTED`，P06 Vio dependency = `NONE`。

### P07 Contradiction Detector（用户正式验收）

**当前状态：** P07、P07 Engine side 与 P07-01—P07-12 均为 `ACCEPTED`，P07 Vio dependency = `NONE`。

**当前作用：** 只消费 P06 COMPLETE、consumable 且 snapshot/trace/route/manifest/fragment hash 一致的结果；可信 resolver 把 fragment 密封为结构化 claim，按 proposition 与 scope 检测 `EPISTEMIC`、`EVIDENTIAL`、`COGNITIVE` 三类不兼容，不能形成可信 claim 的材料不猜测。Detector 不按 recency、confidence 或 Authority 数值选赢家，LOVE/HATE 等心理矛盾明确不触发。

**审计与写边界：** case 保存 contested/isolated disposition、verification task、append-only resolution/reopen/supersession history 和 referral；`direct_state_write_allowed=false`、`evolution_commit_allowed=false`。非权威 repository 使用 canonical JSON/hash、精确 replay、跨重启和加载期篡改验证，但不成为第二事实、状态、Memory、Timeline 或人格权威。

**P07 第二轮返修：** 五类 resolution evidence 先在可信记录中绑定适用命题、scope 和来源；验证输出再密封具体 case/revision/hash、snapshot、claim 集合与动作。audit 字段逐项匹配证明，仓储 format v3 在追加和恢复时重新调用 verifier；仅有类型和自洽 hash 不能绕过目标关联验证。

**P08 验收时的后续边界（历史）：** P08 已正式验收（D-052），不扩大方案 A 或生产能力；P09 正式运行接线仍未开始；合法 resolution 只是可审计结果，不直接调用生产 Evolution。

**现行接线：** P09 正常运行链集成已由用户正式验收，D-053 保留施工与返修历史、D-054 记录验收，状态为 ACCEPTED；P07 resolution 仍不直接推进 Authority，合法后续持久化继续走原 Action Gate/Evolution。P09 接线没有扩大 P08 的生产能力边界。

## 4. Awakening 唤醒系统

## 当前整体边界

当前十层已经形成 Continuity Engine v0.1 的底层连续性原型。目标实时状态闭环中的 SubjectState 读取/保存、Memory 接口、StateMutation/Event、Evolution、Action Gate 和 durable Capability 暂停—恢复协议核心已经具备；P02 已在 Engine 内完成宿主中立 Fake 模型能力闭环，Vio V4、受控 S4 与首次 S4-Live 则提供既有真实结果回流历史。模型结果必须返回原 Thinking 并继续进入 Action；模型回复与状态演化不强制绑定，没有获批 `UPDATE_STATE` 时不创建状态变化且 revision 保持不变。P02 默认路径为 `changed=false`、revision `0→0`，真实模型状态演化仍未验收。

后续任何扩展都必须继续区分：

- 内部模型、规则、接口或确定性替身已经存在。
- 真实外部 Provider、平台、存储、执行器或计费系统已经连接并完成验收。

只有第二类实际完成后，才能把对应真实能力从“未来扩展”调整为“已完成”。
