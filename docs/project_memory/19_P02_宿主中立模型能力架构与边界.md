## 2. 定位与权威边界

P02 建立 Engine 内部、宿主中立、可替换的模型执行能力层。模型是 Thinking 可请求的能力，不是 Subject；`SubjectState`、revision、Event、StateMutation、Evolution 和最终主体表达仍由 Engine 权威控制。

唯一结果链保持为：

```text
ContinuityInteractionService
  → CapabilityRequest(model.generate)
  → 原 ThinkSession = WAITING_CAPABILITY
  → Provider Profile / Budget Gate
  → host-neutral ModelProvider Port
  → ProviderExecutionFact
  → CapabilityResult
  → 原 ThinkSession 恢复
  → ThinkingResult
  → Action
  → ReplyComposer
  → FirstRoundSuccessResult
```

P02 没有建立第二套 CapabilityRequest、CapabilityResult、ThinkSession、operation journal 或 completed result ledger。`model.generate` 仍是 Thinking 的直接 Capability 路径，不进入 Planner。Provider 候选不能直接成为最终主体表达，不能写 SubjectState、推进 revision、创建 Event/StateMutation，也不能绕过 Action 或 ReplyComposer。默认表达路径为 `changed=false`。

## 3. 模块与职责

- `domain/model_provider.py`：Profile、执行请求、执行事实、查询结果、dispatch attempt、执行记录与 synthetic usage/test-credit 类型；不包含 SubjectState。
- `services/model_provider_ports.py`：宿主中立 `ModelProvider`、`ModelProfilePolicy` 和 `ModelExecutionRepository` Ports。
- `services/model_profile_policy.py`：显式选择唯一启用 Profile；未知、禁用或启用 fallback 的配置失败关闭。
- `services/model_capability_service.py`：把 Provider 执行事实驱动进现有 E5-A，并负责预算、查询优先、幂等、恢复与 delivery checkpoint。
- `storage/json_model_execution_repository.py`：P02 execution、usage 与 test-credit 的原子 JSON 账本；所有身份和历史只允许单调追加或补齐。
- `interfaces/local_model_capability_app.py`：Engine 本地、依赖注入式装配；不创建网络 transport。
- `testing/fake_model_provider.py`：完全本地、确定性、可脚本化且可查询的 Fake Provider/Fixture；只用于测试，不是真实 Provider Adapter。

`DeferredCapabilityThinkingProvider` 新增可选内部 provider ID，以便 P02 的 ThinkSession 使用 `engine-host-neutral-model-capability`。默认值仍保留旧 E5-A 标识，既有目录和测试兼容行为不变。

## 4. 持久化、幂等与恢复

P02 execution 以 `capabilityRequestId` 确定唯一 execution identity，并保留 `operationId`、`requestId`、`idempotencyKey`、`inputHash` 和 Profile 快照。每次被允许的 dispatch 在 Provider 调用前持久化稳定 attempt identity。Provider 返回后依次持久化执行事实、成功 usage/test-credit、CapabilityResult 和 delivery/completed checkpoint。

进程在 Provider 返回后、Engine execution ledger 落账前退出时，恢复必须先按原 attempt identity 查询 Provider；Fake Provider 可以返回原执行事实。响应已经由 Engine 完成但调用方或 P02 delivery checkpoint 未收到时，恢复使用 E5-A completed result ledger 精确重放，并补齐 P02 delivery/completed 状态。重复 request 不新增 Provider execution、usage、test-credit、Thinking、Action 或主体结果。

`UNKNOWN` 和 timeout 的 retry class 为 `query`，必须查询原 Provider execution；结果仍不确定时保持 UNKNOWN，不得盲目重试。`FAILED_RETRYABLE` 只允许通过显式 retry 入口创建下一 attempt；已发生的成功 execution 不得再次执行。
