## 可实际运行的 C1 入口

在 Engine 仓库根目录运行：

```powershell
$env:PYTHONPATH='src'
$env:PYTHONDONTWRITEBYTECODE='1'
python -m continuity_engine.testing.p09_core_runner --scenario golden
python -m continuity_engine.testing.p09_core_runner --scenario long
```

入口自动创建独立临时 P01 sandbox，不接受正式 data-dir 初始化目标；会输出 `isolated_evidence_root` 和结构化 `c1-report.json`。Golden 通过正常 LocalIntegrationApp 依次运行 Direct、Information Need、复杂 Planner 与静默行动，重放完成结果并检查零新增写入。宿主 Port 在 Engine composition root 组装，不从测试模块向运行服务注入测试专用交互链。Fixture 使用明确的 synthetic 身份、权限、精确请求确认、Fake Adapter；运行时禁止创建 socket，无 Vio/真实 Provider/凭据需求。

Long 固定 30 个逻辑日、30 轮、30 个新增事件；每 10 轮使用新进程重新打开同一 P01 sandbox，真实重启点在第 10、20 轮之后。每段会重放上一段最后一条请求，验证相同结果、零新效果/费用/写入；逐轮检查候选与输入预算、事件到记忆计数、单一 ledger 请求数、完成结果数、SubjectState revision、合成效果/积分和文件字节数，记录 CPU/墙钟耗时。它不重读全量聊天，不是生产时长 soak，不以多次 unittest 回归冒充长期运行。
