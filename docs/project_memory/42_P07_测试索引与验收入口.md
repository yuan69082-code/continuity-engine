## 5. Golden / fault / zero-write 证据

- P06 snapshot 中既有 confirmed cognition 与 experiential/external/raw evidence 的不一致形成一个稳定 `COGNITIVE` case；Summary 保持 `derived_summary` 并被 isolated，不升权。
- 每个 case 生成 verification task；五类 basis 只能由可信 `ResolutionEvidenceVerifier` 密封，调用方 `verified=True` 无权自证；`reopen()`/`supersede()` 不接受裸 hash。
- COMPLETE Result 强制绑定 trace 的 subject/environment/snapshot/detector version；即使重算内部 hash 也不能跨边界拼装。
- case/repository 只保存 `canonical_value_hash`，凭据样式、超长文本和任意 scalar 原值不落盘；重启/hash/replay 保持一致。
- 只有可信 source-version binding 证明严格新版本替代旧版本时才接受 supersession；旧→新、缺失、同版本、跨源/边界、互相或循环声明拒绝。
- verified 用户更正只追加 resolution audit，不修改状态；仓储重启后 hash/status/history 一致；新独立证据追加 reopen。
- LOVE/HATE 两个 Psychological claim 明确产生 0 case、2 个 NOT_APPLICABLE。
- 无结构化 claim 的正文或 conflict marker 不被猜测为矛盾。
- resolver fault 以 `P07_CLAIM_RESOLVER_FAILED` 归因，repository 保持空。
