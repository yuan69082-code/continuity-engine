## 实时状态闭环目标

```text
PlatformObservation / 合法内部触发
→ Continuity Engine 读取 SubjectState、Memory 与允许使用的事实
→ Perception → Thinking
→ 模型结果返回 Continuity Engine 并继续进入 Thinking / Action
→ ActionDecision
   ├─ 未批准 UPDATE_STATE：不创建状态变更，revision 保持不变
   └─ 合法批准 UPDATE_STATE：内部 Event / StateMutation → Evolution → SubjectState，revision 按合法演化结果推进
```

模型文本不能直接成为 StateMutation，模型回复不意味着状态必然变化；回复生成和状态演化是有关联但不强制绑定的两个结果。当前已完成闭环所需的状态、Memory 接口、Mutation/Event、Evolution、Action Gate 和持久化框架；真实模型调用及其通过正式契约和 Vio 能力通道返回引擎的连接尚未完成，应归入工程总档案的未来阶段 8。

## 愿景驱动的正式运行形态（未来）

工程总档案将长期系统关系定义为：

```text
用户
  ↓
Vio 前端
  ↓
Vio 平台后端
  ↕  Continuity Integration Contract
Continuity Engine
  ↕  通过 Vio 管理的能力通道提出请求并接收结果
模型 / Tool / MCP / 设备
```

正式运行时，引擎应作为独立持续运行的核心服务，保持自己的进程、状态存储、时间系统、唤醒机制和接口，并通过正式版本化契约与 Vio 平台后端通信。二者是数据库独立、边界独立的平行系统；Vio 前端只连接 Vio 平台后端。外部能力结果必须返回引擎继续进入 Thinking / Action，但只有合法批准的 `UPDATE_STATE` 才能创建内部 Event/StateMutation 并经 Evolution 改变 SubjectState；否则 revision 保持不变。

本节全部属于未来目标。当前 v0.1 只有本地 HTTP、调试前端、进程内 API 和内部框架，没有正式 Vio 契约连接、真实模型或工具通道，也没有独立常驻自主运行能力。

下列阶段是工程总档案 v1.0 的推荐后续路线，均为**未完成或待立项**，不能因现有接口已经预留而写成已实现：

### 阶段 8：AI 模型接入

让真实 GPT、Claude 或本地模型通过 Vio 管理的能力通道参与 Thinking。模型是引擎可调用的理解、思考和语言能力，不接管主体身份或状态；模型结果返回引擎继续进入 Thinking / Action，只有 Action 合法批准 `UPDATE_STATE` 才进入内部 Event/StateMutation 与 Evolution。需要先确定隐私、结构化输出、超时重试、模型降级和资源策略。

### 阶段 9：MCP 与外部记忆库

在现有 Memory 管理接口和 ContinuityMCPAdapter 边界上连接真实长期记忆系统。当前没有真实 MCP 传输或外部长期记忆存储。

### 阶段 10：正式前端应用

建立面向真实用户的产品入口。Vio 前端只连接 Vio 平台后端；Vio 平台后端与 Continuity Engine 作为边界独立、数据库独立的平行系统通过正式版本化契约协作。Vio 负责用户、会话、平台事实、现实权限与安全确认、外部能力通道、托管和展示；Continuity Engine 仍是连续状态和 SubjectState 的唯一权威。现有本地 HTTP 和调试前端只是最小开发入口，不代表本阶段已经完成。

### 阶段 11：自主学习完善

在现有受控 Learning 框架上完善用户画像、技能学习、证据质量、审核和策略版本；不得演变为未经确认的自动永久人格修改。

### 阶段 12：自主运行

把引擎部署为具有独立进程、状态存储、时间系统、唤醒机制和受控接口的持续运行核心，在资源、权限和确认约束下形成可持续的 Wake → Perception → Thinking → Action 循环。远期可逐步支持时间/环境感知、自身兴趣与目标、内部思考和是否表达或行动的决定。后台调度、主动联系、外部执行以及与 Vio 平台后端的正式版本化契约连接当前均未实现。

## 工程配套里程碑建议

### v0.1 仓库基线

README 与包描述已经同步；后续仍需由项目所有者决定 LICENSE、CI、本次档案提交和版本标签，不增加主体能力。

### v0.2 可替换基础设施

优先考虑 ActionSession 持久化、数据格式迁移策略、统一配置、日志/可观测性和更明确的多主体注册机制。

### 外部能力里程碑

真实 MCP、外部记忆、AI Provider、Execution Engine、认证和生产部署必须分别立项、批准和安全评审，不能因接口已预留而默认进入核心。
