# P03 时间、来源、修正与撤销语义

> 当前状态：P03 / P03 Engine side = `ACCEPTED`（用户于 2026-08-30 正式验收）
> P03 Vio dependency：`NONE`；P04 后续独立获权并于 2026-09-01 正式 `ACCEPTED`

## 1. 三时间

| 字段 | 含义 | 权威限制 |
| --- | --- | --- |
| `occurredAt` | 客观事实发生的时间 | 不因迟到记录而改写 |
| `observedAt` | Engine 或来源观察到事实的时间 | 必须不早于 occurredAt |
| `recordedAt` | 事实声称进入 Engine 权威 Event 历史的时间 | 必须不早于 observedAt；显式值不得晚于实际 appliedAt |

所有时间必须带时区，比较与序列化统一为 UTC。新入口显式测得三时间时标记 `EXPLICIT`；只缺一个时间时确定性合并并标记 `PARTIALLY_COALESCED`；旧调用和旧 JSON 只有 occurredAt 时三者合并并标记 `LEGACY_COALESCED`。`time_basis` 必须与实际提供/合并情况一致。`apply_event` 只读取一次权威时钟形成 `appliedAt`；显式 recordedAt 可以早于或等于 appliedAt，但不能晚于 appliedAt。coalesced 时间不能被解释为三个独立测量结果。

## 2. 记录顺序与语义顺序

JSON Event 历史保留真实追加顺序；Timeline 按 `occurredAt → observedAt → recordedAt → eventId` 生成语义顺序。乱序写入或迟到事实不会重排、重写或删除 Event Store。Timeline 的排序仅是查询投影。

## 3. 历史分类与状态变化

FACT、OBSERVATION、INTENTION、CORRECTION 和 REVOCATION 无论 occurredAt 是否迟到都只能无 mutation 追加。它们不得携带 StateMutation 倒写当前 SubjectState。若当前状态确需变化，必须由当前合法 Action Gate 形成新的 `STATE_CHANGE` Event，经 Evolution 推进 revision，并以 `caused_by` 引用历史事实。既有 LEGACY/interaction 兼容路径继续存在，但不赋予这些新分类状态写权限。

## 4. 身份与来源

- `eventId`：Engine 内部不可变唯一身份。
- `sourceEventId`：可选来源侧稳定身份；不能冒充 eventId。
- `correlationId`：可选链路/请求相关身份；不能取代 eventId 唯一性。
- `sourceKind`：经过验证的来源类别；`source` 保存具体 producer 名称。
- evidence：只允许结构化公开证据引用，不保存 Provider 隐藏 Chain-of-Thought。

P03 test-only Fixture adapter 只构造 Event 候选，不写仓储。显式调用 SubjectStateService 后 Event 才进入历史；PlatformObservation 仍不能自动转为 Event。

## 5. 修正与撤销

```text
原 Event（保持不变）
  ← CORRECTION Event / corrects reference
  ← REVOCATION Event / revokes reference
```

- target 必须与引用 Event 属于同一 Subject。
- target 必须在真实写入历史中先于引用 Event 存在。
- correction/revocation 只能追加，目标缺失、前向或跨主体引用失败关闭。
- Timeline 可派生 corrected/revoked/superseded；原 Event 和 StateUpdateRecord 永不删除。
- 对同一目标，revocation 保持终态优先；后续 correction 仍作为历史存在，但不能把已撤销目标重新标成 active/corrected。

## 6. 精确重复

Event canonical body 包含三时间、time basis、分类、来源、身份、证据、引用、metadata、scope 和 mutation。`apply_event` 先从已经持久化的 state/history 查找 eventId：相同 body 立即幂等返回原历史 update 与当前 state，并明确 `idempotent_replay=true`；不同 body 立即抛出 `EventIdentityConflictError`。两条既有身份路径都不读取当前 clock。只有新 Event 才生成 appliedAt 并执行 future recordedAt 门，所以恢复时钟早于原 recordedAt 不会破坏已提交历史。
