## 1. 状态与停止词

### 阶段状态

- `NOT_STARTED`：尚未开工，没有阶段实现或验收结果。
- `IN_PROGRESS`：已获授权且正在施工。
- `BLOCKED`：已开工但存在无法继续的明确阻塞。
- `IMPLEMENTED_NOT_ACCEPTED`：本地实现和核查完成，但监工/用户尚未验收。
- `ACCEPTED`：规划监工窗口核查通过且用户明确验收。

### 运行与依赖状态

- `NOT_READY`：能力或门禁尚未满足，不能进入当前行为。
- `BLOCKED`：当前施工项存在已确认阻塞，停止该项。
- `DEPENDENCY_MISSING`：所需文件、服务、工具、权限或证据不可取得。
- `RECOVERABILITY_NOT_READY`：正式 Subject / Owner Domain 的生产恢复地基未达到 P20/P21 要求。
- `RESEARCH_WORLD_UNAVAILABLE`：Research World 独立总线、Adapter、网络、凭据、数据或审计不可用；不得回退到现实执行路径。

## 2. Planning Conflict 入口

发现规划与真实代码、依赖、环境、平台或现有架构冲突时，立即执行 `STOP CURRENT ITEM`，返回 `PLANNING_CONFLICT`，并记录：

1. 当前施工项。
2. 原规划要求。
3. 当前真实冲突。
4. 无法直接落地的原因。
5. 保持原方案所需条件。
6. 改变方案会改变的目标或依赖。
7. 可选方案。
8. 推荐方案。
9. 推荐理由。

用户决定前不得绕开冲突、修改依赖顺序、继续其他写入或以临时实现掩盖问题。用户决定应追加到 `04_决策记录.md` 或对应施工日志，不得静默覆盖旧决定。

## 3. 恢复与回滚总边界

- P01 的 Snapshot/Rollback 只允许作用于一次性测试主体、实验和 Research Sandbox。
- P17 可复用 P01 的设计与验证方法，但不能把测试快照当作正式主体恢复能力；P17 的直接阶段依赖只有 P16 `ACCEPTED`。
- P20/P21 负责正式 Subject、Owner Domain、备份、灾难恢复、Schema/Subject Migration 和 Data Recovery，但不是 P17 阶段的前置依赖。
- P20/P21 未验收前，依赖正式恢复的高风险现实能力必须保持 `RECOVERABILITY_NOT_READY / NOT_READY / Disabled` 或正式 Feature Gate 关闭。这是能力开放门，不改变阶段顺序，也不授权提前施工 P20/P21。
- Git revert 可用于代码历史的正常版本化回退；禁止使用 `git reset`、删除仓库、清除数据根目录或测试 Snapshot 改写正式 Subject 生命历史。
- Event 历史、已完成 operation/result、已发生现实副作用、已确认主体演化和审计事实均属于禁止静默回滚对象。

## 5. Reality Boundary 专门禁区

唯一现实行动链是：

```text
Subject → Thought → Desire → Will → Decision → Structured Action
→ Capability Resolution → Permission / Resource / Recoverability Check
→ Reality Boundary → World Adapter → Reality Effect
```

Reality Boundary 只能控制现实副作用，不得限制或修改 Thought、Emotion、Desire、Will、Personality、Relationship、Self-Narrative 或内部心理冲突。P21 的 Security Wall 同样不得被扩张为主体行为对齐或思想审查层。
