## 工程总档案 v1.0 未完成主清单

以下能力是工程总档案明确列出的后续工作，当前均未完成真实接入：

1. **真实 AI 模型接入：** 尚未连接 GPT、Claude 或本地模型；ThinkingProvider 只是可插拔接口。
2. **真实 MCP：** 尚无真实 MCP server/client、传输、鉴权或平台连接；ContinuityMCPAdapter 只是接口设计。
3. **外部长期记忆：** Memory 管理层不保存长期记忆，尚未连接外部记忆库、向量库或真实数据库。
4. **真实动作执行：** Action 只生成决定与计划，没有 Execution Engine，也不会联系用户或调用工具。
5. **自动后台运行：** 有单次 Wake 和资源感知调度框架，没有常驻守护进程、自动定时运行或主动联系。
6. **真实 Token 计费：** 有 ResourceState、预算与确定性使用记录，没有模型实际 usage、价格或账单系统。
7. **正式前端应用：** 现有本地 HTTP 和调试前端可用于开发验证，但不等于面向用户的正式产品前端。

目标实时状态闭环中的 SubjectState 读取/保存、Memory 接口、StateMutation/Event 和 Evolution 已具备内部框架；“真实模型生成回复并在每轮自动完成闭环”仍包含在第 1 项中，尚未实现。

## 计划完成

以下事项不阻止当前源码归档，但会影响后续可靠性：

### 1. ActionSession 持久化

- 当前只有 `InMemoryActionRepository`。
- 若需要跨重启完整行动审计，应新增仓储协议实现和迁移测试。

### 2. 数据格式版本与迁移

- 当前多个模块使用本地 JSON。
- SubjectState、Permission、Learning 和 Resource 已有 v1 格式或 schema 标识；Awakening、Thinking 以及跨模块数据仍缺少统一版本策略。
- 需要兼容读取、迁移工具、备份和失败恢复策略，避免模型字段演进破坏旧数据。

### 3. 配置与路径管理

- 统一本地数据目录、端口、subject_id、预算和运行模式配置。
- 区分开发、测试和未来部署环境。

### 4. 可观测性

- 统一结构化日志、request/session 关联、错误分类和审计查询。
- 继续坚持只记录思考摘要，不保存完整思维链。

### 5. 多主体管理

- 代码模型多处保留 subject_id，但缺少完整主体注册、隔离和生命周期管理。
- 需要先定义权限边界和数据隔离，再扩展多主体运行。

### 6. 兼容入口治理

- 为旧 `wake_perception_thinking_service.py` 定义正式弃用策略。
- 处理其对内存 Action 仓储的兼容性依赖，避免长期形成分层例外。

### 7. 文档与版本同步机制

- 每次阶段完成后同步本档案、README、CHANGELOG 和测试数量。
- 通过 CI 或评审清单防止文档再次落后于实现。

### 8. 统一资源检查入口

- ResourceState、ResourceManager、ResourceAwareWakeScheduler 和各类资源申请入口已经存在。
- 当前 AwakeningService 仍可直接执行唤醒，Learning 的 ResourceManager 也是可选依赖。
- 后续应通过统一编排入口保证所有主动运行都执行资源检查，同时保留底层服务的可测试性。
