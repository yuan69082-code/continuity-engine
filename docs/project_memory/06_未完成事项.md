## 工程总档案 v1.0 未完成主清单

以下能力是工程总档案明确列出的后续工作，当前均未完成真实接入：

1. **真实 AI Provider 与后续现场验收：** P02 已完成宿主中立 Port、可替换 Profile、本地 Fake Provider、预算和故障/恢复矩阵；首次 S4-Live 另有一次受控真实 Provider 历史。尚未完成的是 P22 的真实 SDK/网络/凭据/可信费用、更多供应商现场验证、日常正式身份或生产治理，也未验证真实模型触发 `UPDATE_STATE`。
2. **真实 MCP：** 尚无真实 MCP server/client、传输、鉴权或平台连接；ContinuityMCPAdapter 只是接口设计。
3. **外部长期记忆：** Memory 管理层不保存长期记忆，尚未连接外部记忆库、向量库或真实数据库。
4. **真实动作执行：** Action 只生成决定与计划，没有 Execution Engine，也不会联系用户或调用工具。
5. **自动后台运行：** 有单次 Wake 和资源感知调度框架，没有常驻守护进程、自动定时运行或主动联系。
6. **真实 Token 计费：** P02 有单次 1024、每日 10240 synthetic Token 和每次成功 1 test-credit 的持久化测试账本；这些不是供应商用量或价格。首次 S4-Live 的 Vio 执行账本报告 177/9/186 Token，但生产可信供应商账单、价格与最终费用仍未闭合并后置 P22。
7. **正式前端应用：** Vio F1 已完成固定本地受控链路，Engine 仓库也有调试前端；二者都不等于面向一般用户的生产前端。

目标实时状态闭环中的 SubjectState 读取/保存、Memory 接口、StateMutation/Event、Evolution、Action Gate 和 durable Capability 暂停—恢复核心已具备；P02 已验证 Engine 内宿主中立模型执行、synthetic usage/test-credit、故障查询和原 ThinkSession 回流，Vio V4、受控 S4 与首次 S4-Live 则是既有真实链路历史。模型回复与状态演化不强制绑定：P02 默认及首次真实试聊均未批准 `UPDATE_STATE`，revision 保持不变；只有合法批准后才能创建内部 Event/StateMutation。真实模型状态演化和 P22 生产 Provider 仍未实现。
