# continuity-engine 项目总览

> 档案基线：`0.1.0`  
> 最近核对：2026-07-22  
> 事实来源优先级：当前代码与测试 > 本工程档案 > README

## 项目是什么

`continuity-engine` 是一个以 `SubjectState` 为中心的数字连续性引擎。它把主体的当前状态、经历引发的状态变化、记忆检索影响、唤醒、感知、思考、行动规划、权限、学习与运行资源组织为可追溯的工程流程。

当前版本的主链路是：

```text
外部输入 / 手动或定时唤醒
        ↓
Event → Evolution → SubjectState
        ↓
Wake → Perception → Thinking → Action
        ↓                         ↓
        └──────── Approved UPDATE_STATE
                                  ↓
                         Event → Evolution
                                  ↓
                            SubjectState
```

项目同时提供接口适配设计和一个最小本地前端，但核心引擎不依赖前端、具体 AI 模型、MCP 服务或外部记忆库。

## 为什么存在

普通对话系统通常把一次会话当作主要边界。这个项目尝试把“主体在时间中的连续存在”变成显式、可保存、可审计的工程对象，解决以下问题：

- 当前主体是谁、处于什么状态。
- 某个状态为什么发生变化，由什么事件导致。
- 唤醒后看到了什么、感知到了什么、为什么做出某个决定。
- 权限、长期特征和资源预算如何随时间变化。
- 更换前端、模型、记忆库或开发人员时，核心连续性逻辑仍可保持。

## 项目不是什么

当前项目不是：

- AI 模型训练框架，也不修改模型权重或参数。
- 情绪模拟器；现有 `emotion_state` 只是主体状态的一部分，不等于情绪生成系统。
- 已能自主联系用户或操作外部工具的 Agent。
- 真实 MCP、外部记忆库、OpenAI/Claude API 或生产数据库集成。
- 生产级 Web 服务、身份认证、支付或真实 Token 计费系统。
- 把内部完整思维链长期保存的系统；日志只保存可审计摘要。

## 最终目标

最终目标是形成一个长期运行、可移植、可审计、受权限和资源约束的连续性内核：

1. 主体状态能够跨进程和跨交互持续存在。
2. 所有正式状态变化都有事件、原因、前后差异和 revision。
3. 感知、思考、行动、学习彼此分层，不绕过演化入口。
4. AI 模型、记忆库、MCP、前端和执行器均可替换。
5. 外部行动必须经过权限、风险、资源和确认约束。
6. 工程状态能够被后续开发窗口、AI 助手或开发人员快速接管。

## 核心架构

### 分层

```text
frontend
  仅输入、展示和 API 通信
        ↓
interfaces
  API / HTTP / MCP Adapter / Skill Adapter / 安全门
        ↓
services
  用例编排、上下文组装、流程协调
        ↓
domain
  模型、规则、枚举和不可变约束
        ↕
storage
  仓储协议的 JSON 或内存实现
```

### 核心边界

- `domain` 管理模型和规则，不依赖上层接口。
- `services` 组装流程，不把数据库读取责任塞给领域引擎。
- `storage` 负责保存和恢复，不决定业务含义。
- `Perception` 只能观察和理解，不能修改 `SubjectState`。
- `Thinking` 的直接输入是 `PerceptionResult`，模型执行器通过 `ThinkingProvider` 插拔。
- `Action` 只决定和规划，不执行真实外部行动，也不直接修改状态。
- 正式状态变化唯一入口是 `Event / StateMutation → Evolution → SubjectState`。
- 外部入口必须经过 `PermissionContext` 和 `ResourceManager`。
- 采用 `expected_revision` 防止并发覆盖。

## 当前可替换点

- 记忆：`MemoryRetriever`、`MemoryInfluenceRecorder`。
- 思考：`ThinkingProvider`。
- 行动权限：`PermissionProvider`，并可由权限连续层生成上下文。
- 行动会话：`ActionRepository`，当前只有内存实现。
- 主体、权限、学习、资源、唤醒和思考记录：当前使用本地 JSON 仓储。
- 外部接入：API、MCP Adapter、Skill Adapter 和前端客户端。
