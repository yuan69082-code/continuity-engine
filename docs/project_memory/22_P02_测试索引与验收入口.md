## 2. 行为与故障覆盖

`test_p02_model_capability.py` 覆盖 Profile 选择、默认确认参数、不可用配置、成功闭环、多轮、同请求重放/冲突、generation/network/timeout/UNKNOWN/retryable/terminal/cancelled/expired、查询终态单调解析、`NOT_EXECUTED` retry gate、部分/耗尽日预算、Provider 越限审计、usage/test-credit 加载期逐字段篡改拒绝、空白输出、冻结兼容字段、无网络/凭据和无隐藏 Chain-of-Thought 字段。

`test_p02_model_recovery.py` 覆盖：

1. model execution reserved 后退出；
2. Provider dispatch identity 持久化后退出；
3. Provider 已返回、Engine 尚未落事实；
4. Provider fact 已保存、usage 尚未保存；
5. usage 已保存、CapabilityResult 尚未准备；
6. CapabilityResult 已准备、E5-A 尚未接收；
7. Engine 已完成、P02 delivery checkpoint 尚未保存；
8. delivery checkpoint 保存后退出；
9. UNKNOWN/TIMEOUT 查询 resolution 已保存、后续交付尚未完成；
10. E5-A CapabilityResult 已持久化、operation checkpoint 尚未完成；
11. 原 ThinkSession 已恢复、operation thinking checkpoint 尚未完成；
12. Action 已完成、domain checkpoint 尚未完成；
13. completed result 已保存、调用方尚未收到；
14. 重建运行图后继续下一轮。

每个恢复场景都从持久目录重建运行图，验证原 requestId、operationId、capabilityRequestId、ThinkSession 和 completed result 继续使用，并从 P02 权威账本断言成功 Provider execution=1、usage/test-credit=1、accepted CapabilityResult=1；Wake/Thinking/Action/主体结果不重复，revision 保持 0。

## 3. 验收证据边界

- Provider 原始候选经 CapabilityResult → 原 ThinkSession → Thinking → Action → ReplyComposer 后才成为 Engine 响应。
- P02 默认表达路径 `changed=false`、revision `0→0`、engineUpdateId=null；模型候选不能直接更新状态。
- 同一请求的重复 execution、test-credit、subject result 和 Action 增量均为 0。
- `UNKNOWN` 先查询且无法确认时保持 UNKNOWN。
- UNKNOWN/TIMEOUT 原始 fact 不覆盖；FOUND/NOT_EXECUTED 只以同 attempt 的追加 resolution 解析，查询 resolution checkpoint 可跨崩溃恢复。
- 当日剩余额度在 Provider 调用前收窄 `maximumTokens`；越限执行事实和实际 synthetic usage/test-credit 留存审计，但候选不进入 Thinking/Action/ReplyComposer。
- 每次加载 usage/test-credit 都与唯一成功 Provider fact 逐字段核对，reference/provider/model/tokens/day/time/credits 任一漂移均失败关闭。
- E4/E5 HTTP 读取正文前 POST 拒绝在响应 flush 后通过统一半关闭与固定缓冲短时丢弃收口；401 不等待完整未授权正文。404/405/401/503/415/Transfer-Encoding/Content-Length/413 的外部状态码和 JSON 未变。
- 正式 `.continuity-data` 使用项目内 `tree_inventory_hash` 在测试前后比对；P02 测试根全部为临时目录。
- 六份冻结 Schema 和 `pyproject.toml` 前后 hash 必须不变。
- Vio dependency、network access、credential access、real Provider execution 和 real cost 均为 `NONE/0`。
