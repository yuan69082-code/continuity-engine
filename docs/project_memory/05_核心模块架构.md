# Continuity Engine 核心模块架构

> 适用版本：Continuity Engine v0.1
> 核对日期：2026-08-01
> 状态口径：已完成表示当前 v0.1 约定范围内的实现和测试已存在；部分完成表示内部框架已建立，但真实接入、统一入口或完整持久化仍有缺口；未实现表示只有规划，没有当前实现。

## 架构定位

Continuity Engine 是位于 AI 模型之外的连续性层。十个核心模块共同维护主体状态、变化原因、上下文理解、行动约束、长期演化和运行资源；它们不负责把某个具体 GPT、Claude 或本地模型固化进核心。

十层不是简单的单向调用栈。`SubjectState` 是中心状态，`Evolution` 是正式状态写入入口；Memory、Awakening、Perception、Thinking 和 Action 形成观察与决策链，Permission 和 Resource 提供约束，Learning 通过证据生成需要交给 Evolution 的变化建议。

```text
PlatformObservation / 合法内部触发 / Wake
        ↓
Memory → Perception → Thinking → Action
                     │           │
                     │           └─ Approved UPDATE_STATE
                     │                         ↓
                     └──────────────── Event / StateMutation
                                               ↓
Permission ────────约束───────────────→ Evolution ←──── Learning
Resource ─────────资源约束────────────→    ↓
                                        SubjectState
```

正式状态变化必须经过 `Event / StateMutation → Evolution → SubjectState`。Perception、Thinking、Action、Permission 和 Learning 均不得绕过该入口直接修改 SubjectState。

## 1. SubjectState 主体状态系统

**当前状态：已完成。**

**当前作用：** 保存主体当前连续状态和 revision，是整个引擎的中心状态对象。当前包含 identity、relationship、continuity、temporal、intentions 和 emotion_state 六个状态分区，并支持领域校验、JSON 持久化和重启恢复。

**未来扩展方向：** 建立统一 schema 版本与迁移工具、备份恢复、生产级仓储、跨进程并发控制和更完整的多主体隔离。扩展字段时必须保持兼容迁移，不能无依据重置连续状态。

## 2. Evolution 状态演化系统

**当前状态：已完成。**

**当前作用：** 作为 SubjectState 的唯一正式变化入口，接收 Event/StateMutation，校验 expected_revision 和影响范围，应用确定性变化规则，并生成包含 before/after 差异和原因的 StateUpdateRecord。

**未来扩展方向：** 完善状态规则版本化、跨模块事务编排、冲突处理、迁移审计和更丰富的演化策略。未来模型或执行结果必须先返回 Thinking / Action；只有 Action 合法批准 `UPDATE_STATE`，引擎才能创建 Event/StateMutation，外部结果不能直接写入 SubjectState。

## 3. Memory 管理层

**当前状态：部分完成。**

**当前作用：** 管理 MemoryRetrievalRequest、候选相关性判断、MemoryRetrievalResult 和 MemoryInfluenceRecord，通过可插拔 Retriever/Recorder 接口向其他模块提供相关记忆及影响摘要。当前测试使用确定性替身，不拥有长期记忆正文存储。

**未来扩展方向：** 接入经过批准的 MCP、向量库、知识库或其他外部长期记忆实现，并补充数据所有权、删除更正、召回评估、敏感信息和迁移策略。接口已存在不等于真实记忆库已经连接。

## 4. Awakening 唤醒系统

**当前状态：部分完成。**

**当前作用：** 提供手动、定时和事件唤醒的单次运行框架；每次唤醒创建 WakeSession，读取当前状态、近期演化和相关记忆，形成 WakeContext，并返回 SLEEP、THINK、CHECK_MEMORY 或 READY 决策。

**未来扩展方向：** 建立受 ResourceManager 统一约束的后台调度、生命周期管理、频率上限、熔断、停止开关和用户可见性。当前没有常驻守护进程，也不会自主联系用户。

## 5. Perception 感知层

**当前状态：已完成。**

**当前作用：** 将 SubjectState、Wake 上下文、MemoryRetrievalResult、近期事件和当前时间转换为关注点、时间感知、关系感知、记忆影响、观察、内在驱力和摘要。Perception 是 Thinking 的唯一直接输入层，并保持只读。

**未来扩展方向：** 在单独批准后增加更丰富的环境、关系、时间和冲突理解，以及可信度和来源治理。扩展不能演变为未经设计的情绪模拟，也不能让 Perception 直接修改 SubjectState。

## 6. Thinking 思考层

**当前状态：部分完成。**

**当前作用：** 接收 PerceptionResult，通过 ThinkSession 保存感知摘要、预算、结果和关联信息，并以 ThinkingResult 输出是否产生想法、是否建议更新状态、请求记忆、等待或未来联系用户。E5-A 增加 `WAITING_CAPABILITY` 状态：原 ThinkSession 可在 Perception 后持久暂停，待受约束 CapabilityResult 返回后恢复并完成；ThinkingProvider 保持可插拔，当前仍不调用真实模型，也不保存完整思维链。

**未来扩展方向：** 由 Vio V4 对接 GPT、Claude、本地模型或模型路由 Provider，并补齐现实权限、安全确认、供应商调用与可信 usage；Engine 侧继续扩展提示版本、超时重试、隐私、降级和资源策略。真实模型接入后仍不得直接修改 SubjectState。

## 7. Action 行动层

**当前状态：部分完成。**

**当前作用：** 把 ThinkingResult 中的行动倾向转换为 ActionIntent、权限/风险/资源评估、ActionDecision 和 ActionPlan。当前只决定和规划；仅批准的 UPDATE_STATE 可以转换为 Event 并交给 Evolution，CONTACT_USER 和 USE_TOOL 等计划不会真实执行。

**未来扩展方向：** 在独立立项后建立 Execution Engine、确认令牌、幂等、步骤状态、失败补偿、沙箱和工具适配器，并为 ActionSession 增加跨重启持久化。ActionPlan 不能被当作已执行结果。

## 8. Permission 权限连续层

**当前状态：已完成（v0.1 内部范围）。**

**当前作用：** 记录 PermissionState、授权范围、能力、状态和 PermissionChangeRecord，并通过 PermissionContext 向 Action 等模块提供当前权限视图。当前支持创建、查询、限制、撤销、历史、能力检查和 JSON 恢复。

**未来扩展方向：** 对接真实账号、设备、MCP、浏览器、邮箱、日历或工具权限，并解决授权同步、凭据存储、scope 映射、过期撤销和重新确认。内部权限状态完成不代表任何真实平台权限已经取得。

## 9. Learning 自主学习框架

**当前状态：部分完成。**

**当前作用：** 将经历整理为 LearningEvent、PersonalityTrait 和 LearningRecord，通过多次独立证据、置信度、验证、明确确认和回滚控制长期特征变化。固化或回滚只生成交给 Evolution 的 Event，不训练模型，也不直接修改 SubjectState。

**未来扩展方向：** 增加人工审核队列、证据质量、冲突证据、冻结特征、策略版本、用户画像和技能学习治理，并补齐统一 Learning → Evolution 事务编排。未经确认的自动永久人格改变仍不允许。

## 10. Resource 资源管理

**当前状态：部分完成。**

**当前作用：** 使用 ResourceState、RuntimeMode、TokenUsageRecord、ResourcePolicy 和 ResourceManager 管理确定性预算、资源申请、使用记录、降级和延迟；Thinking、Learning、Wake 与外部接口已有资源检查连接点。

**未来扩展方向：** 将所有主动运行入口统一收口到资源检查，并接入真实 Provider usage、模型价格、计算时间、并发额度和日/月配额。当前没有真实 Token 自动统计、真实计费、支付或资源自动购买。

## 当前整体边界

当前十层已经形成 Continuity Engine v0.1 的底层连续性原型。目标实时状态闭环中的 SubjectState 读取/保存、Memory 接口、StateMutation/Event、Evolution、Action Gate，以及 Engine 侧 durable Capability 暂停—恢复协议核心已经具备；Vio V4 和真实模型执行仍未连接。模型结果必须返回原 Thinking 并继续进入 Action；模型回复与状态演化不强制绑定，没有获批 `UPDATE_STATE` 时不创建状态变化且 revision 保持不变。

后续任何扩展都必须继续区分：

- 内部模型、规则、接口或确定性替身已经存在。
- 真实外部 Provider、平台、存储、执行器或计费系统已经连接并完成验收。

只有第二类实际完成后，才能把对应真实能力从“未来扩展”调整为“已完成”。

## 外部连接边界：第一阶段连接与 E5-A Capability 核心（不计入十层主体能力）

**当前状态：第一阶段机器契约、test-only 验收链、正式本地回环连接及 Engine E5-A 均已完成。** Engine E1 机器契约基础、E2 数据与持久化基础、E3 test-only 确定性领域闭环、test-only JSONL Runner 和双方 test-only 共享验收均已完成；Engine E4 正式本地回环 HTTP/JSON 服务也已完成。Vio V3 × Engine E4 第一阶段正式本地回环双方验收已经通过，正式基线为 Engine `189441f9bad2a34119b4ef10365a4385ed0949cc`、Vio `35780da56c72b822fc018702dfe5e90674ab0fcb`。E5-A 又完成 Engine 侧 durable Capability 暂停—恢复核心。当前仍没有 Vio V4、真实模型、外网连接、生产部署、Vio 公共对话 API 或用户前端真实对话链路。

**当前作用：** E1 用类型化 `ContinuityInteractionRequest`、PlatformObservation、message fact 和固定 SubjectBinding fixture 表达并严格验证 v1.1 第一轮输入。E2 提供不可变成功结果与错误 envelope、最小 stateProjection、SubjectState/投影 hash、固定 Binding 本地恢复，以及不可覆盖的 completed result ledger 和跨重启精确重放。E3 以独立、test-only、进程内 `ContractTestAdapter` 接线，将已验证平台事实只读送入 PerceptionResult，并用确定性进程内替身贯通真实 Action Gate、必要时 Evolution 和可恢复 operation journal。JSONL Runner 只属于 test-only 双方验收桥，不是正式服务或生产 Adapter。

E4 通过唯一 `ContinuityInteractionService`、正式持久化 SubjectBinding、显式 init、串行回环 HTTP、completed/not_found/recovery_required 查询和 durable crash recovery 提供正式本地连接。Vio V3 已真实通过 HTTP transport 调用独立运行的 E4；completed、not_found、recovery_required、POST 响应丢失和 Engine/Vio 分别或同时重启恢复均已通过验收。SubjectState 仍是 Continuity Engine 的唯一权威；PlatformObservation 绝不直接成为内部 Event/StateMutation，只有 Action 合法批准 `UPDATE_STATE` 才能进入 Evolution。

E5-A 使用独立 `continuity-capability/v1` 协议，由 Engine 决定是否请求外部模型能力、持久化不可变请求和 attempt，并将原 ThinkSession 置为 `WAITING_CAPABILITY`。结果经同一服务提交后必须通过 Schema、hash 和身份关联验证，再由解释器恢复原 Thinking 并进入 Action/回复；默认 deterministic 模式和 v1.1 不变。该链当前只在 Engine 内完成，没有真实外部执行。
