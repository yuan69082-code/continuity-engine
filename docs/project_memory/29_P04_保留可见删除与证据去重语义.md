# P04 保留、可见、删除与证据去重语义

> 当前状态：P04 Engine side = `ACCEPTED`（用户于 2026-09-01 正式验收）
> 决定来源：D-043

## 1. 保留与温度

- episodic、semantic、relational Memory 默认没有硬性到期时间。
- P04 不执行自动过期或物理删除，不存在后台线程或 P11 Scheduler。
- HOT/WARM/COLD/ARCHIVED 只表达活跃度和召回距离，不表达事实真伪或删除许可。
- 默认容量 HOT 300、WARM 3000、COLD 30000 均来自可替换 `MemoryActivationConfig`。
- 达到容量时，显式 maintenance 先重算 activation，再把低分项逐级降温；记录和证据链继续存在。
- time decay 只是评分因子之一；importance、recent access、relation relevance、emotional weight 和 unique reinforcement 同时进入可解释评分。

## 2. 可见范围

正式默认值只有 `ENGINE_PRIVATE`。P04 仅允许 Engine 内部服务、临时测试根和授权只读测试入口访问。`RepositoryMemoryRetriever` 普通检索只读读取 ACTIVE 且温度为 HOT/WARM/COLD 的 Memory，不返回 ARCHIVED；ARCHIVED 仍保留在仓储中，可由显式 load、维护、审计和授权 trace 访问，不表示删除、失效或事实为假。关闭 Feature Gate 时返回空集合；普通检索不写 access、reinforcement、Memory 或 Learning。

P04 不读取 Vio 仓库/数据/进程，不使用网络、API Key、真实 Provider、MCP、外部数据库或向量服务。本阶段隔离不是长期产品禁令：P05/P06/P16/P22 仍按冻结顺序接入 Context、外部能力和 World Adapter。

## 3. 根证据身份

每个 Memory 必须有非空、唯一且可从 source chain 追溯的 `root_evidence_ids`。Event 和合法 Message 来源映射为稳定根身份；派生自 Memory 时继承其根身份。Repository MemoryCandidate 中的 root/source/kind/evidence/visibility/status/temperature/version 为正式保留 provenance，调用方 metadata 不得覆盖、伪造或删除；MemoryInfluence 与后续 Learning 使用密封后的值。Consolidation 与 Learning 均按根身份去重：

```text
同一 Event → Memory A → Summary A
           → Memory B → Summary B
```

上图在 reinforcement 或 Learning evidence count 中仍只贡献一次。检索、摘要重建、服务重启或不同 Memory/Summary identity 不产生新证据。真正独立的根来源才可以增加一次计数。

## 4. 冲突边界

同 consolidation identity 不同 canonical 输入是 identity conflict。每次请求都在单一 Memory 原子文档保存 operation identity、canonical input hash/body 以及首次 result Memory 的 identity/revision/canonical hash；重复根 alias 也必须持久登记。exact replay 始终从 append-only Memory history 返回首次确切版本，即使目标随后 reinforcement、terminal propagation 或重启也不漂移、不强化、不写新 revision。alias candidate 不能借用结果 Memory 伪造来源：其 source Memory 必须已存在、同 subject/environment、非前向，candidate roots 必须从自身 Event/Message/Memory source chain 完整追溯；保存与加载都失败关闭。相同 kind/evidence/scope 中出现互不兼容的内容时，P04 不覆盖、不投票、不自动选边，而以显式证据冲突失败关闭。完整 Contradiction Detector 属于 P07，本阶段没有提前实现。

## 5. correction/revocation/deletion

- 三种信号都必须引用已存在、同 Subject 的 Memory。
- P04 追加新的 terminal Memory version 与 `MemoryLineageRecord` 墓碑；原版本仍在历史中。
- lineage 根至少包含来源 Event 的稳定根，其他根只允许来自目标、合法 replacement 或其既定来源链；保存与加载均拒绝无关根、缺失根、跨主体、缺失/前向 replacement 和篡改。
- correction/revocation/deletion 关联的 Event 身份只作证据引用，P04 不删除或改写 Event。
- 依赖目标 Memory 的 ACTIVE DerivedSummary 在同一原子事务中追加为 INVALIDATED。
- 重新生成只读取当前 ACTIVE Memory，并产生单调递增的新摘要版本。
- `DELETION` 在 P04 是传播墓碑，不是生产永久删除；P12 负责 Intentional Forgetting，P20/P21 负责生产删除、备份和恢复语义。

## 6. 明确禁止

- DerivedSummary 直接成为 Event、StateMutation、SubjectState 或 Learning 的独立根事实。
- 多次召回或措辞确定自动提升 confidence/authority。
- 删除最旧 Memory 解决容量问题。
- 用 Summary Store、Summary Engine 或第二 Memory Store 建立平行权威。
- 从 P04 跳到 Router、Composer、Scheduler、外部记忆、生产删除或 Vio 重连。
