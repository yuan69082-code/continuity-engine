# 工程路线图

## 编号说明

历史需求在 Action 阶段后重新使用了“第五、六、七阶段”编号。为避免接手者误读，本文件前半部分按实际施工顺序记录 1—12，并在对应位置注明原规划编号；这些是已经发生的施工记录。工程总档案 v1.0 另行定义未来产品路线的阶段 8—12，见文末“工程总档案后续路线”。两套编号不可互相替代。

当前总阶段结论：原规划七阶段的底层连续性框架已经建立，Continuity Engine v0.1 原型完成。接口、适配器或本地调试入口存在，不等于真实模型、MCP、外部记忆、正式前端或外部执行已经接入。

## 实时状态闭环目标

```text
用户输入
→ SubjectState 读取
→ Memory 检索
→ 模型回复
→ StateMutation
→ Evolution
→ SubjectState 保存
```

当前已完成闭环所需的状态、Memory 接口、Mutation/Event、Evolution 和持久化框架；真实模型调用及其与每轮回复前后状态读写的自动连接尚未完成，应归入工程总档案的未来阶段 8。

## 阶段 1：SubjectState 最小状态系统

**目标：** 建立主体状态的最小可运行模型和跨进程 JSON 保存/读取能力。

**完成内容：** 建立 SubjectState 六个状态分区、revision、领域校验、服务层和 JSON 仓储。

**新增文件：** `domain/models.py`、`services/subject_state_service.py`、`storage/base.py`、`storage/json_repository.py`、CLI 入口及对应测试。

**验证结果：** 完整 SubjectState 可保存，关闭后重新加载，状态与 revision 连续。

**当前状态：** v0.1 范围完成。

## 阶段 2：Event 与状态演化

**目标：** 从“状态存储系统”升级为“状态变化系统”。

**完成内容：** 建立 Event、影响范围、演化规则、变化前后差异、StateUpdateRecord、expected revision 并发保护和事件/变化持久化。

**新增文件：** `domain/events.py`、`domain/evolution.py`、相关服务与测试；扩展 `storage/json_repository.py`。

**验证结果：** 事件能够确定性地产生状态差异和 revision 递增，冲突 revision 被拒绝，记录可追溯。

**当前状态：** v0.1 范围完成。

## 阶段 3：Memory 管理层

**目标：** 建立不负责长期存储的可插拔记忆检索与影响管理层。

**完成内容：** MemoryRetrievalRequest、候选、相关性判断、MemoryRetrievalResult 和 MemoryInfluenceRecord；定义 Retriever/Recorder 端口。

**新增文件：** `domain/memory.py`、`services/memory_ports.py`、`services/memory_service.py`、`tests/test_memory_service.py`。

**验证结果：** 可用确定性替身完成检索、排序、过滤和影响记录，不依赖数据库或 MCP。

**当前状态：** 部分完成；内部管理层和接口已完成，外部长期记忆库、MCP 接入和真实数据库存储未实现。

## 阶段 4：Awakening System

**目标：** 建立“醒来 → 查看自身 → 做出决策”的自主运行基础。

**完成内容：** 手动/定时唤醒、WakeSession、WakeContext、最近事件与变化、记忆请求、四种 WakeDecision 和日志。

**新增文件：** `domain/awakening.py`、`domain/awakening_rules.py`、`services/awakening_service.py`、`storage/json_awakening_repository.py`、`tests/test_awakening.py`。

**验证结果：** 每次唤醒可追溯原因、状态 revision、所见内容、决策原因和完成状态。

**当前状态：** 部分完成；单次手动/定时/事件唤醒框架完成，没有后台常驻调度，且并非所有直接唤醒路径都强制经过统一资源入口。

## 阶段 5：Thinking Engine

**目标：** 建立独立于聊天的内部思考流程，并预留可插拔模型执行器。

**完成内容：** Thinking 直接接收 PerceptionResult；ThinkSession 保存感知摘要、预算、结果及 Wake/Perception 关联信息；同时建立 ThinkingResult、ThinkingProvider、TokenBudget 接口和摘要日志。

**新增文件：** `domain/thinking.py`、`services/thinking_ports.py`、`services/thinking_service.py`、`storage/json_thinking_repository.py`、`tests/test_thinking.py`。

**验证结果：** THINK 决策可创建会话并返回标准结果；没有调用真实 AI，也不保存完整思维链。

**当前状态：** 部分完成；Thinking 接收 PerceptionResult，通过 ThinkSession 保存上下文摘要、预算、结果和关联信息；真实模型 Provider 未接入。

## 阶段 6：Perception Engine

**目标：** 在 Thinking 前建立统一感知层，使思考只直接接收感知结果。

**完成内容：** PerceptionContext、当前关注、时间感知、关系感知、记忆影响、观察、内在驱力与摘要；固定 Wake → Perception → Thinking 边界。

**新增文件：** `domain/perception.py`、`domain/perception_rules.py`、`services/perception_service.py`、`tests/test_perception.py`，并更新思考编排。

**验证结果：** 感知可由状态、唤醒、事件、记忆和时间确定性生成；Perception 不修改 SubjectState。

**当前状态：** v0.1 范围完成。

## 阶段 7：Action Engine

**目标：** 将思考倾向转为受权限、风险和资源约束的可审计行动决定与计划，不执行真实行动。

**完成内容：** ActionContext、Intent、Decision、Step、Plan、Session；七种行动类型；权限、风险、资源评估；UPDATE_STATE 经 Event/Evolution 落地；完整编排服务。

**新增文件：** `domain/action.py`、`services/action_ports.py`、`services/action_permissions.py`、`services/action_evaluators.py`、`services/action_service.py`、`services/wake_perception_thinking_action_service.py`、`storage/in_memory_action_repository.py`、`tests/test_action.py`。

**验证结果：** 无倾向、权限缺失/撤销、确认要求、高风险、资源不足、revision 冲突和完整演化链路均有测试。

**当前状态：** 决策规划完成；真实执行禁止；ActionSession 尚未持久化。

## 阶段 8：Permission Continuity Layer（原规划阶段 5）

**目标：** 长期记录主体拥有的权限、能力范围和变化历史，并与行动时权限判断区分。

**完成内容：** PermissionState、PermissionChangeRecord、PermissionContext、创建/查询/限制/撤销/历史/能力检查和 JSON 恢复。

**新增文件：** `domain/permissions.py`、`services/permission_service.py`、`storage/json_permission_repository.py`、`tests/test_permissions.py`。

**验证结果：** 权限可创建、限制、撤销、追溯并在重启后恢复；Action 可读取 PermissionContext；服务不直接修改 SubjectState。

**当前状态：** v0.1 范围完成；没有真实平台权限接入。

## 阶段 9：Personality Evolution & Self Learning（原规划阶段 6）

**目标：** 让长期特征经多次经历、验证和确认后可控演化，不训练模型。

**完成内容：** LearningEvent、PersonalityTrait、LearningRecord、LearningContext；候选、证据累积、验证、固化和回滚；通过 Event/Evolution 修改状态。

**新增文件：** `domain/learning.py`、`services/learning_service.py`、`storage/json_learning_repository.py`、`tests/test_learning.py`。

**验证结果：** 单次事件不固化，三次独立一致证据与阈值规则生效，未验证内容不固化，错误学习可回滚，记录可恢复。

**当前状态：** 部分完成；规则型受控学习框架完成，没有自动用户行为分析、模型训练或无需确认的永久人格改变。

## 阶段 10：Token & Resource Management（原规划阶段 7）

**目标：** 为主动运行建立统一的确定性资源约束。

**完成内容：** ResourceState、RuntimeMode、TokenUsageRecord、ResourcePolicy、ResourceManager 和资源检查入口；支持预算申请、消耗、降级、延迟、模式切换和历史记录。

**新增文件：** `domain/resources.py`、`domain/resource_policy.py`、`services/resource_manager.py`、`services/resource_aware_wake_scheduler.py`、`storage/json_resource_repository.py`、`tests/test_resources.py`。

**验证结果：** Thinking、Learning、Wake 均可经过资源检查；超预算被阻止或降级；状态重启恢复。

**当前状态：** 部分完成；资源管理结构和检查入口已完成，但尚未实现所有路径强制经过统一资源入口，也没有真实 Token 统计或计费。

## 阶段 11：API / MCP / Skill Adapter（原集成阶段 8）

**目标：** 在不修改核心逻辑的前提下建立外部调用连接层。

**完成内容：** 统一 API 请求响应、核心只读视图、权限与资源安全门、MCP Adapter 工具表面和 SkillAdapter 协议。

**新增文件：** `interfaces/models.py`、`interfaces/ports.py`、`interfaces/security.py`、`interfaces/core_views.py`、`interfaces/api_service.py`、`interfaces/mcp_adapter.py`、`interfaces/skill_adapter.py`、`tests/test_interfaces.py`。

**验证结果：** 外部请求不能绕过权限/资源检查，不能直接修改 SubjectState；适配器接口存在且可测试。

**当前状态：** 部分完成；进程内 API、安全门和适配器设计已完成，没有真实 MCP 传输或平台 Skill 连接。

## 阶段 12：Frontend Integration（原集成阶段 9）

**目标：** 提供最小可运行的输入、结果展示和调试状态入口。

**完成内容：** FrontendClient、同源本地 HTTP 服务、聊天界面、状态/revision/最近事件调试视图和用户交互编排。

**新增文件：** `interfaces/http_server.py`、`interfaces/local_frontend_app.py`、`services/user_interaction_service.py`、`frontend/index.html`、`frontend/app.js`、`frontend/client.js`、`frontend/styles.css`、`frontend/__main__.py`、`tests/test_frontend_integration.py`。

**验证结果：** 前端可发请求、API 可接收、核心链路可处理并展示结果；浏览器端不保存核心状态；历史测试保持通过。

**当前状态：** 部分完成；本地演示入口完成，不是生产前端或生产服务器。

## 工程总档案后续路线

下列阶段是工程总档案 v1.0 的推荐后续路线，均为**未完成或待立项**，不能因现有接口已经预留而写成已实现：

### 阶段 8：AI 模型接入

让真实 GPT、Claude 或本地模型实现 ThinkingProvider，并把模型回复接入实时状态闭环。需要先确定隐私、结构化输出、超时重试、模型降级和资源策略。

### 阶段 9：MCP 与外部记忆库

在现有 Memory 管理接口和 ContinuityMCPAdapter 边界上连接真实长期记忆系统。当前没有真实 MCP 传输或外部长期记忆存储。

### 阶段 10：正式前端应用

建立面向真实用户的产品入口。现有本地 HTTP 和调试前端只是最小开发入口，不代表本阶段已经完成。

### 阶段 11：自主学习完善

在现有受控 Learning 框架上完善用户画像、技能学习、证据质量、审核和策略版本；不得演变为未经确认的自动永久人格修改。

### 阶段 12：自主运行

在资源、权限和确认约束下形成可持续的 Wake → Perception → Thinking → Action 运行循环。后台调度、主动联系和外部执行当前均未实现。

## 工程配套里程碑建议

### v0.1 仓库基线

README 与包描述已经同步；后续仍需由项目所有者决定 LICENSE、CI、本次档案提交和版本标签，不增加主体能力。

### v0.2 可替换基础设施

优先考虑 ActionSession 持久化、数据格式迁移策略、统一配置、日志/可观测性和更明确的多主体注册机制。

### 外部能力里程碑

真实 MCP、外部记忆、AI Provider、Execution Engine、认证和生产部署必须分别立项、批准和安全评审，不能因接口已预留而默认进入核心。
