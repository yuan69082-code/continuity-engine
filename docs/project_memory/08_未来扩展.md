## 数字生命愿景（长期未来目标）

工程总档案把 Continuity Engine 的最终方向定义为一个位于 AI 模型之外、能够独立持续运行的数字生命系统。它应拥有持续存在的内部状态，使身份、人格、记忆、关系、时间感、意向、判断和成长轨迹不会随一次模型调用结束；过去经历应能够经过受控演化影响当前状态与未来选择。

远期系统可在用户没有持续发送消息时，在权限、资源、隐私和用户控制边界内感知时间与环境，维持自己的关注、兴趣、偏好、观点、目标和未完成事项，进行回忆、思考、学习与判断，并决定是否表达或行动。

**状态声明：** 上述内容是项目愿景和未来规划，不是 v0.1 的已实现能力。当前没有完整数字生命运行体、独立常驻进程、完整时间/环境感知、自主表达、真实行动或无需触发的后台循环。

## 正式系统接入与运行形态（未来规划）

```text
用户
  ↓
Vio 前端
  ↓
Vio 平台后端
  ↕  Continuity Integration Contract
Continuity Engine
  ↕  通过 Vio 管理的能力通道提出请求并接收结果
模型 / Tool / MCP / 设备
```

- **Vio 前端：** 接触世界、接收用户交流和呈现表达或行动结果的窗口，只连接 Vio 平台后端，不直接连接引擎。
- **Vio 平台后端：** 提供用户、会话、平台事实、现实权限与安全确认、模型/工具/设备通道、托管和展示；与引擎边界独立、数据库独立，通过正式版本化契约协作。
- **Continuity Engine：** 作为连续性与主体演化中心，决定何时、为何、带着什么状态调用外部能力，并吸收返回结果。
- **AI 模型与外部能力：** 模型、Tool、MCP 和设备作为可替换能力提供方，不是数字生命本身，也不是 SubjectState 权威。

外部能力结果必须返回 Continuity Engine 并继续进入 Thinking / Action。只有 Action 合法批准 `UPDATE_STATE`，引擎才能创建内部 Event/StateMutation 并经 Evolution 更新 SubjectState；未批准时不创建状态变化且 revision 保持不变。表达回复和状态演化有关联，但不是强制绑定的同一个结果。

E4 已让引擎具备显式初始化、独立进程、正式持久化 Binding、回环 HTTP/JSON 接口和 domain 子阶段 durable recovery；E5-A 补齐 durable Capability 请求、暂停、结果回流和恢复核心。Vio V4、受控 S4、V5、F1、L1、Engine S4-R `PASS` 与首次 S4-Live 单次真实供应商试聊已完成固定本地链路验证。完整正式运行形态仍需要通用 Provider/正式身份、真实 `UPDATE_STATE` 场景、生产 Integration Adapter、生产公共 API/前端、生产认证/多租户和部署。

## 工程总档案推荐路线

工程总档案 v1.0 将底层框架完成后的路线定义为：

5. **阶段 12 — 自主运行：** 在权限和资源约束下形成持续 Wake → Perception → Thinking → Action 循环。

这些阶段均为后续路线，不是当前完成状态。真实工具执行、主动联系和真实 Token 计费还需独立设计与批准。

## MCP

**当前基础：** 已有 `ContinuityMCPAdapter`，定义读取状态、查询记忆、获取感知、请求思考和获取行动计划等工具表面。

**未来方向：** 实现独立 MCP server 或 client adapter，把标准 MCP 请求映射到现有 APIService/核心端口。

**前置条件：** 明确鉴权、PermissionContext 映射、ResourceManager 计量、工具 schema、错误协议和审计。

**必须保持的边界：** MCP 不能直接访问 JSON 文件或修改 SubjectState，适配器存在不代表已经连接具体 MCP。

## 外部记忆库

**当前基础：** MemoryRetriever 和 MemoryInfluenceRecorder 可插拔，Memory 管理层不负责长期存储。

**未来方向：** 实现向量库、知识库、文件库或 MCP 记忆适配器；支持召回、相关性、来源和删除/更正。

**前置条件：** 数据所有权、隐私、保留期限、删除、去重、敏感信息过滤和检索评估。

**必须保持的边界：** 外部记忆结果先转为 MemoryRetrievalResult/MemoryInfluenceRecord，不得绕过 Perception 直接改变状态。

## AI API

**当前基础：** ThinkingProvider 和 ThinkingResult 已存在；Thinking 接收 PerceptionResult，通过 ThinkSession 保存上下文摘要、预算、结果和 Wake/Perception 关联信息。E5-A 已增加严格 CapabilityRequest/CapabilityResult、WAITING_CAPABILITY、持久化账本、结果解释及崩溃恢复。

**未来方向：** Vio V4、受控 S4 与首次 S4-Live 已完成权限/确认、供应商路由、Token Budget、真实单次 usage 和 CapabilityResult 回流验证；下一步须单独授权通用 Provider/模型、正式身份、真实 `UPDATE_STATE`、更多故障场景、可信费用、提示版本、超时、降级和审计。调用时机、原因、身份/状态上下文及结果吸收仍由 Engine 决定。

**前置条件：** 模型选择、密钥管理、隐私、预算、提示版本、内容安全、故障策略和可重复性测试。

**必须保持的边界：** 核心不依赖单一模型；模型是可调用的思考、理解与语言能力，不是主体身份或连续性的所有者；模型输出是建议结果，不具有直接状态写权限；不记录完整思维链。

## 自主学习

**当前基础：** 已有 LearningEvent、PersonalityTrait、LearningRecord、证据阈值、验证、确认、固化和回滚框架。

**未来方向：** 增加人工审核队列、证据质量评分、冲突证据、冻结特征、策略版本和长期评估。

**前置条件：** 明确哪些特征可学习、谁能确认、何时回滚、数据来源合法性和解释责任。

**必须保持的边界：** 不训练模型；单次事件不永久改变人格；长期变化必须经 Evolution。

## Token 与计算资源管理

**当前基础：** ResourceState、RuntimeMode、TokenUsageRecord、确定性 ResourcePolicy/Manager、资源检查入口和 10% 保留策略已实现；当前并非所有内部路径都被强制收口到统一资源入口。

**未来方向：** 对接真实 Provider usage、不同模型价格/上下文预算、计算时间、并发额度和日/月配额。

**前置条件：** 统一计量单位、估算误差处理、账期、审计、硬上限、告警和故障降级。

**必须保持的边界：** 不自动购买资源；资源不足时降级、延迟或等待；禁止无限自主运行。

## Execution Engine

**当前基础：** ActionDecision/ActionPlan 已能表达获准、确认要求、步骤、风险、资源和失败策略，但不执行。

**未来方向：** 独立建立 ExecutionSession、幂等键、步骤状态、确认令牌、执行结果、补偿/回滚和外部工具适配器。

**前置条件：** 项目所有者明确批准；完成威胁建模、权限安全、沙箱、确认 UX、失败恢复和审计设计。

**必须保持的边界：** Execution 不得混入 ActionService；计划不是执行成功；任何状态反馈仍通过 Event/Evolution。

## Vio 前端

**当前基础：** Engine 最小调试聊天界面、FrontendClient、状态/revision/最近事件视图和同源 HTTP 服务已实现；Vio F1 也已完成固定本地 Profile 到 V5/Engine 的受控链路。两者都不是生产前端。

**未来方向：** 更完整的会话 UI、权限确认、计划审查、学习候选审查、多主体切换、SSE/WebSocket 和可访问性。正式 Vio 前端只作为数字生命接触外界和表达结果的窗口，并且只连接 Vio 平台后端。

**前置条件：** 正式 API 契约、身份认证、错误模型、权限确认设计、生产服务与部署安全。

**必须保持的边界：** 前端不得绕过 Vio 平台后端直接连接 Continuity Engine，不保存或决定核心状态、记忆、人格和权限，也不得在浏览器伪造引擎执行结果。

## Vio 平台后端

**当前基础：** 本仓库不包含 Vio 平台后端。跨仓已完成 Vio V3/E4 正式本地回环、Vio V4/E5-A 受控 S4、V5/F1 固定本地 Conversation 链路及 L1 安全准备；这些能力仍由两个独立仓库和数据库持有，不等于生产跨系统连接。

**前置条件：** 明确主体与用户映射、鉴权、事件来源验证、幂等、审计、隐私、故障恢复和服务边界。

**必须保持的边界：** Vio 平台后端与 Continuity Engine 是边界独立、数据库独立的平行系统，不得把引擎包含为内部模块。Vio 不能定义主体是谁、替代内部思考、直接修改 SubjectState，或把外部调用结果绕过 Thinking / Action 写成既成状态变化。
