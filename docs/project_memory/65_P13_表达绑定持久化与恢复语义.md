# P13 表达绑定、持久化与恢复语义

P13 沿用正常 `ContinuityInteractionService.submit()`：C1 组装 Context → Thinking/ThinkSession → Action Gate 与原 Direct/Optional Planner/E5-A → Expression → 原 Domain/Evolution/完成记录。通过 `build_continuity_core(..., expression_policy=ExpressionPolicyService(...))` 显式开启；`None` 是兼容旧路径的关闭配置。没有测试专用的第二交互执行链，也不修改冻结接口文件。

## 内容与决定

`ThinkingResult.expression_mode` 是内部可选的已形成意图，允许 RESPOND、SILENCE、REFUSE、QUESTION、CONFRONT、DEFER、PURSUE；旧数据没有此字段，重新序列化也不添加 null 字段。旧 Thinking 使用原 should_wait/default RESPOND。模型冻结契约不增加字段：原 model.generate 仍经原解释器进入 ThinkSession，默认表达模式保持兼容。TEST Thinking Port 可以提供七模式的明确结构化合成输入。

Expression 不从用户消息重新推断心理内容、不产生新判断。它读取现有 `identity.expression_preferences`、`relationship.interaction_preferences`、C1 已有简化情绪投影及当前 Context，选择已声明的受限格式。`concise` 去掉空白行但不丢弃句子；`formal` 使用引文格式；同时有显式 `emphasis` 偏好及已有投影 intensity≥0.5 才使用强调格式。0.5 是本地呈现规则，既不修改情绪数值，也不引入 P14 情绪动力。

正文必须完整保留上游内容和态度。超过表达预算会明确失败，不裁掉否定、末句或来源来伪造完整表达。此版本只提供确定性的空白/格式变换，不声称能够证明任意自由自然语言改写与原判断等价。已有模型负责 Thinking 生成，表达物化 Port 不另调模型、扣费、安排任务或访问网络。

## 原请求绑定

`ContinuityCoreContext.expression_enabled` 与原 Perception 一同进入持久化 ThinkSession 及 Context hash。关闭时字段省略，保留旧 Context/hash 兼容性。原 P13 请求不能因 operation 中删除这个字段而降级为 legacy：独立 ThinkSession 输入及既有恢复比较会拒绝矛盾。

表达绑定包括 request ID/hash、operation、subject、binding/version、input revision、原 ThinkSession ID/结果、Router request ID、原 Action 完整结构及原 Context binding hash。服务额外核对 Action 必须等于 operation 已保存的 Action；不能把另一 Action 或另一请求套在同一段 Thinking 上。

最终 `ExpressionDecision` 和 `ExpressionArtifact` 存在原 operation journal 的 `domain.expression`，不是新账本。保存的表达内容等于原完成响应内容，模式/正文/身份必须与原 Thinking 及 Action 一致。原 domain 的不可变规则继续生效。完成记录缺少 artifact、正文 hash/模式矛盾或缺少原绑定必须失败关闭。

## Port 与 Trace

本地纯呈现 Port 只得到不可变决定及已形成可见正文；候选须精确回引 decision hash、mode、原正文及 Engine 允许的样式。替换正文、反转态度、替换模式/绑定都拒绝。Engine 在调用前后核验当前 Context/权限及完整输入，拒绝调用期间的失效。

Trace 只含 hash、模式、状态、固定理由码和样式标志，不复制正文、偏好原文、凭据或 Provider 隐藏推理。正式表达产物保存的是本次可见正文；它不因此取得事实或主体状态 Authority。

## 状态和消费

| 状态/结果 | 语义 |
|---|---|
| SUBJECT_EXPRESSION / REFUSE 等模式 | 原主体决定的可见表达；REFUSE 不代表平台拒绝 |
| SUBJECT_SILENCE / SILENCE | 有明确主体决定的真实空表达；无呈现 Port 调用 |
| PLATFORM_DENIED | 原 Action Gate 拒绝/待确认；空表达但不冒称主体沉默或主体拒绝 |
| ExpressionGenerationError | 物化失败/候选篡改/预算不够；不是 SILENCE，不保存虚假完成产物 |
| WAITING_CAPABILITY | 仍等待原 E5-A 模型请求；没有表达产物 |
| NOT_MATERIALIZED / PENDING_COMPLETION | 未物化或事实完成记录尚未收口；不能当作已表达 |
| CURRENTLY_UNAVAILABLE | 原事实已核实，但旧表达因 Context/权限/版本失效不可再次消费 |

非冻结的 Engine 内部读入口 `app.adapter.service.expression_outcome(request_id)` 返回结构化状态。在 CURRENTLY_UNAVAILABLE 时只返回已核实 request/operation/revision/update 身份，不返回正文。正常 submit/query 不能通过重复请求释放旧失效正文。缺失/冲突回执不返回上述成功事实视图，仍按原 E5-A 规则先拒绝。

已实际提交的 Evolution 即使在 Context 过期/撤权后，仍可恢复原 update/event/revision 归账；Expression 不重复写状态。此时首次提交恢复可报告表达不可消费，事实 checkpoint/完成账目仍保存，内部读入口给出 verified_facts。新 Evolution 仍须通过原当前检查。合法同次首次 UPDATE_STATE 可以先形成表达、再沿原 Gate/Evolution 推进一次 revision；这次主体变化使旧 Context 后续失效，历史表达不会因属于同一请求而获得永久消费许可。

## 崩溃和幂等范围

Thinking 后崩溃恢复原结果，不使用新 Provider/新模式覆盖旧决定。domain checkpoint 后恢复已保存 artifact，零重新呈现/Thinking/效果/计费。物化异常发生在 domain 保存前，原 Thinking/Action checkpoint 保留；显式恢复仅重新运行无外部效果的本地纯物化，不重新 Thinking 或重复原 Action。它不是第二模型重试通道，不支持在 PresentationPort 中隐藏有副作用的 Provider。

UNKNOWN 或冲突 Adapter 回执依旧阻断真实动作成功重放。PURSUE/DEFER 不增加任务、通知或现实执行；真实行动由原 Direct/Planner/Gate 完成。幂等结论限于本地已验证的持久化/Fake 回执，不宣称生产 exactly-once。

P12 lifecycle 通过既有 Router/Composer current exact 检查传播：归档来源使旧表达不可消费，新请求 Context 排除该记忆，不靠重新读全量聊天历史恢复。原 operation 文件已被 P01 C1 Snapshot 纳入，测试分支复制既有内部字段，无新增快照仓储/Authority，不能替代生产恢复。

具体测试和首次失败见 [复核入口](66_P13_测试索引与验收入口.md)；生产表达 Adapter、任意改写等价验证及后续阶段均未开放。
