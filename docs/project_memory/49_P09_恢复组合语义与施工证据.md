## 正常交互与恢复

`ContinuityInteractionService` 在原 Perception checkpoint 中保存 `ContinuityCoreContext`，同一个 Perception 进入原 ThinkSession 和实际 Thinking Provider。模型模式仍使用原 `CapabilityRequest.input.perceptionSummary`，规范化序列化保证等待重启时字节一致；不修改六份外部 Schema 或另建上下文 Store。

正常链完成原 Action Gate 决定后，将明确的 Information Need/Action Intent 交给既有 P08 Direct/Optional Planner。内部 `memory.lookup`、`expression.emit`、`contact.send`、`silence` 使用绑定 Port；C1 Fixture 提供可验证的本地原子回执。模型文本和 Observation 不直接产生 StateMutation；原合法 `UPDATE_STATE` 仍归 ActionEvolutionService/SubjectStateService 所有，C1 不复制该写入链。

每轮新整理最多 64 个尚未整理的 active Event episode，来源事件身份限定 episode scope，保留三时间及 classification。`consolidated_at` 是实际整理时间；同一原子 P04 consolidation operation 保存输入与结果。未处理积压会在 C1 Context、模型缺失计数和结构 Trace 中明确记录，下轮继续处理；不把只处理最近窗口当作全量完成。

新 Thinking 和新动作须重验当前 SubjectState revision、Context 有效期（默认 10 分钟）、来源及精确引用许可、Composer 精确解析和 Memory/Summary Event 根来源。未选中的原始 Timeline 候选不能成为漏查已撤销根来源的理由。P08 仍单独检查当前权限/确认/资源/Recoverability/Reality Boundary。

原请求恢复先查询独立绑定 Adapter 回执。真实成功/失败不因当前 Context 失效而被抹除；失效不能授权重试、新请求或后续步骤。UNKNOWN、查询异常、字符串 `NOT_EXECUTED` 和缺失回执都不能当作明确未执行证明。明确重试入口是 `ContinuityInteractionService.retry_c1_actions(request_id, request_hash)`：只恢复已有 Action checkpoint，仍经 P08 查询和当前门；随后重交原请求取得正常完成结果。外部 HTTP/机器契约没有新增路由。

已完成 C1 请求重放仍独立核实回执。关闭主开关或当轮动作能力不能成为跳过历史回执验证的手段；此类 C1 恢复失败关闭。原本关闭动作能力的回合，其开关保存在 Context 中，后来开启也不能补造动作。经已有 ThinkSession/Action/E5-A 记录核对确属旧格式的请求保持原路径；单独缺少 journal 中的 C1 字段不能证明它是旧请求。P09 不新增通用取消/调度/执行系统，未确认或终止动作通过原 capability ledger 保留状态；不伪造成功的外部 result。

## P01 覆盖与最小情绪

已有 19 个 Snapshot 逻辑组不改名。显式 TEST C1 profile 将 P04 memory 文档纳入 memory 组、P07 非权威审计纳入 test_trace、Fake 独立事实回执纳入 action_sessions、profile 纳入 state_fixture；原 operation/ThinkSession/capability ledger 已覆盖 C1 Context 和请求。固定映射、完整 physical inventory、manifest 外部锚与逐文件 hash 继续校验；缺失或未知文件拒绝。P01 原 memory stub 只为旧测试保留，不是 C1 的第二记忆源。

EmotionState 的内部可选字段为 current_state/intensity/updated_at/confidence/baseline；旧记录缺省时序列化完全保持原结构。有效强度为 `baseline + (intensity - baseline) * 2 ** (-max(0, elapsed_seconds) / 86400)`，取 9 位小数；时间回退不增强，有限比例和带时区时间必须有效。读取只返回计算结果，不保存、不推进 revision。显式 P01 Fixture 的持久化通过原 Event/Evolution；真实运行保存仍须既有合法 Action/Evolution 授权。本轮没有 Scheduler 或完整 Dynamic Mind。

## 失败与修复记录

原始输出及逐次实际测试数量/耗时在 [50 测试索引](50_P09_测试索引与C1运行入口.md) 的 evidence 清单中登记。开发中的失败不覆盖为通过；注入故障并被断言正确捕获属于测试场景，不冒充测试套件失败。

- Snapshot 首次拒绝未映射的 C1 持久化文件；随后补齐固定 profile 和四个文件映射，保留 closed-world 拒绝规则。
- 主开关关闭可能跳过已完成 C1 的回执检查，动作开关重启后缺少当轮记录；修复为持久化当轮动作开关，并对需要 C1 的恢复失败关闭。
- Context 超过时限后仍调用 Thinking；在新 Thinking/执行前加入当前 Context TTL 和授权检查。
- 不同事件共用单一 consolidation scope，触发 P04 证据冲突；改为事件身份限定 episode，跨 episode 的命题矛盾仍由 P07 处理，不合并或选择赢家。
- Composer 只计算正文成本，来源元数据使原模型 4096 字符上限超出；沿用 Composer 裁剪机制，增加内部完整材料成本回调，缺省旧 P06 行为不变；C1 缺失原因按原因计数且不丢失数量，保留模型硬上限。
- 模型等待重启的真实失败来自 emotion 字典恢复后键顺序改变，产生不同的输入字符串；改为规范化排序序列化。旧 E5-A 完整输入关联校验无需放宽。
- 未检索原始 Timeline 候选时，记忆祖先撤销未使 Context 失效；新增所选 Memory/Summary 的 Event 根来源独立复核，读取无写入。
- 测试辅助错误如实保留：模型请求输入字段名、authority 枚举大小写、LocalIntegrationApp 服务访问路径、EventReference 参数顺序、Snapshot 属性位置、Fixture mutation impact scope、异常类型和混合账本两种请求的序列化结构；均按实际领域契约修正，没有减弱原本效果/费用/Authority 断言。
- Windows 长路径暴露 Fixture 路径过长，缩短新 P09 测试根名称；P08 Fake 固定回执时间不适合跨逻辑日，增加可选注入时钟，缺省 P08 行为保持不变。预算计入元数据后，迟到场景改为显式充足的 Context Budget 来验证完整下游材料；独立小预算场景继续要求真实裁剪和缺失提示。

- 只读静态核对脚本首次读取 baseline.json 漏写 UTF-8，触发本机默认 GBK 解码错误；改为显式 UTF-8 后，174 个 Python 文件按 3.11 语法解析通过。另一次只读核对脚本因多余右括号发生 SyntaxError，修正后核对通过；两次读取命令路径/Windows glob 不匹配也已更正。原始输出汇总脚本还曾只匹配复数 tests，误将单项 test 输出当作 JSON，出现 JSONDecodeError；兼容单复数后确认 12 份失败输出全部保留。以上均属辅助工具调用错误，没有写入或修复运行代码/测试，不是项目回归失败。

## 限制

幂等/费用结论仅覆盖已验证的本地 Fake 原子回执，不是任意生产 Adapter 的 exactly-once。长期测试是明确逻辑时长的有界场景，文件和校验耗时随追加历史增长；本轮没有生产性能、全天候运行或任意规模稳定性承诺。P10—P23 未开始，D-054 未创建。


## 第一轮监工返修的恢复语义

新 Action 决策前必须重验 C1 输入；首次 Evolution 查不到原事件时，再用当前 Context、当前时钟、当前权限集合与既有 ActionService 的 Permission/Risk/Confirmation/Resource gate 检查原状态行动。旧批准和旧 action_at 不再充当永久执行许可。Action、domain checkpoint 已存在也不能跳过首次提交前的检查。

若原 Evolution 已实际落盘，按稳定 event_id 查询既有 SubjectState 历史，核实 request/operation、Action/Thinking、mutation/content/reason、event/update 和 revision 的对应关系；不要求过期 Context 重新授权已发生事实。相同验证也用于完成结果重放，读取不产生新状态提交。

完整 C1 Context（含 actions_enabled）在既有 progress、ThinkSession observation 和 Action summary 之间由可选输入 hash 关联；ThinkSession 保留的实际 perception_snapshot 必须与 journal 输入一致。字段缺失或布尔值改动不能将原 C1 降级成 legacy；共同重算输入 hash 也不能掩盖同一 E5-A 已存在的 typed Action。结构绑定只用于一致性，成功/执行失败仍须原可信 Adapter 的独立回执，UNKNOWN 不成为未执行证明。旧格式没有这些可选字段时不强制补写；正常旧模型记录及原本关闭动作的合法记录继续回归。

首轮修复后的提前加载拒绝造成两个 helper ERROR，扩展完成重放的一项 FAIL 及随后 16/16 PASS 分别保存于 [50 返修索引](50_P09_测试索引与C1运行入口.md#p09-repair-01)。这仍是 P09 定点修复，没有新 Authority、第二账本或通用执行引擎。


## 第二轮：缺失 Evolution checkpoint 与失败证据的确定边界

已完成 C1 状态请求是否需要查询原 Evolution，由原 Action 授权、稳定 operation/event 身份、ThinkSession 的写回标记与 event/update ID、完成 projection 的 changed/revision/update ID 共同确定。evolution=null 不再关闭查询。原事实须匹配 subject、前后 revision、event/update ID、mutations、content、event/record reason、Action/Thinking/request/operation 元数据以及 action_engine/internal/state_change 来源。存在状态提交声明却无原 Action 授权，或完成结果/ThinkSession 与原事实不一致，都失败关闭。

已完成请求若只丢失 journal checkpoint，而真实记录及所有原绑定仍可核实，则只读返回原完成结果，不修写 journal、不推进 revision。尚未完成但 Evolution 已真实提交的崩溃恢复，仍由原 `_complete_evolution` 查证原事件后保存必要的既有 checkpoint；当前 Context 过期/撤权不能阻止事实恢复。尚未发生的第一次状态提交仍经过当前 Context 和 Action 授权门。真正旧链路及无状态更新的 C1 请求保持原行为。

`_verify_core_completed` 统一保护 submit、query 和完成结果回调；既有 C1 retry 入口也先核验状态事实。没有新增状态 Authority、事件源、请求账本或执行引擎。测试覆盖及实际失败见 [第二轮索引](50_P09_测试索引与C1运行入口.md#p09-repair-02)。

long 测试 harness 将真实子进程流直接写文件，可捕获失败/中断时在原临时根清理前保留必要输出至独立证据目录。父级 KeyboardInterrupt 与子进程实际退出码分别记录；不猜测历史普通 ERROR 是否中断，不重试失败 segment。只保存命令、阶段、流与时间等测试证据并脱敏，不复制权威数据。历史 segment 10 的 stderr 已丢失且无法补造；本轮受控证明只适用于当前保留机制。


第二轮字节审计补充：未脱敏流以独占二进制写入原始 bytes，脱敏流保存 UTF-8 处理结果；原流长度/hash 与脱敏标记分开。修复前 Windows 换行转换导致长度/hash 不一致的失败及旧样本仍保留，新的受控失败/中断样本在 Fixture 清理后可读且未脱敏 hash 一致，见 50 第二轮索引。
